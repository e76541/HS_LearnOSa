## 第二章 模塊層

### 2.1 分層綱要

```text
ModuleCore(凍結;改動 = breaking change)
├─ module_id / source_id / char_span
├─ article_type / semantic_roles
├─ domain / operations / problem_type
├─ input_type / output_type
├─ cognitive_level / is_skill_signal
└─ confidence / schema_version / extractor

型別本體(隨型別入凍結集時一次性定義)
├─ TeachingModule : concept_core, examples, hooks, limitation
├─ MethodModule   : procedure, constraints(必填,允許值「作者未給」),
│                   preconditions, failure_modes
├─ CaseModule     : context, actions(含事件序), outcome, transferability
└─ AnalysisModule : claim, evidence, assumptions, counterarguments
```

- 匹配引擎僅准讀核心投影(P5);資產提升與練習生成方可讀型別本體。
- 模塊為唯讀證據層:生成後不變,不承載任何流轉狀態。狀態一律住登記層(第六章)。

### 2.1a 素材標註

記憶鉤欄位為帶型別的素材項清單,每項攜帶字元區間回指原文,附屬宿主模塊,不獨立成節點:

```text
hooks: [ { kind: story | quote | formula, char_span, note? } ]
```

- **附屬不脫勾**:模塊拆分時素材隨其字元區間歸屬的子模塊搬遷。
- **不進邊層、不進對齊**:結構層畫模塊間關係時不讀素材;素材對邊層與對齊層皆不可見。
- 公式類素材維持雙記過渡(候選 C5 未結)。
- **實測補充(SRC-002)**:方法型模塊的素材幾乎全為公式類,敘事鉤(故事、金句)集中於教學與案例型模塊——演講素材因此常需跨出鏈外取用,此即背景模塊條款(2.6)與放寬規則的實證動機。

### 2.2 拆分規則

一個模塊可有多個語義角色,但其主要命題必須屬於同一命題簇。**不同簇之命題各有不同外部依賴目標,強制拆分。**簇歸屬或依賴目標無法確定時,標記「待人工覆核」,不自動切分。

同簇判準(至少符合一項):一者詳述另一者;一者例示另一者;兩者共同構成不可分割的機制;移除任一者使另一者語義不完整。不因主題相同而自動合併。

### 2.3 弱策略點規則

方法模塊的約束條件值為「作者未給」時,構成弱策略點:

1. 禁止生成應用型練習(無邊界條件的規則練習訓練過度泛化)。
2. 替代路徑:降轉未知項進問題模型,待第二來源補條件後升級;或生成「邊界獵取」型評估題(此規則何時失效)。
3. 弱策略點為演講問答之優先選題靶點(4.2a 第三幕)。

### 2.4 非技能訊號(r1 拆為兩檔)

技能訊號為否的模塊,依語義角色再分兩檔:

| 技能訊號 | 角色含「背景」 | 身份 | 待遇 |
|---|---|---|---|
| 是 | — | 正常模塊 | 全流程 |
| 否 | 有 | **背景模塊** | 依 2.6 |
| 否 | 無 | 純填充(行銷、鋪陳) | 僅保留字元區間連續性,不進任何下游 |

### 2.5 零散來源(條件式生效)

**定義**:跑完模塊化與邊抽取後,有效模塊數至少一、但內部邊數為零之來源。

**規則**:零散來源僅得掛靠(attach-only)——僅於對齊命中既有登記節點且過人工覆核時完成收錄;未命中者不建模塊,原文退回候選池,待登記簿長出對應節點後再撿回。不自含之片段(依賴外部語境、命題單獨不成立)於管線入口即擋。

**生效條件**:對齊操作可用(6.3)。登記簿空置或極小時本條自動休眠。

**入口三問(規範外操作備註)**:任何存量文字進管線前——一問,有原文未主張之主張否?無則棄。二問,主張獨立成立否?是則為來源,走正常管線。三問,有具體斷邊題現在要用它否?有則作一次性作答素材,答案回填成邊後即棄。三問出口無「以零散身份儲存」一項;「零散」不是系統持有的類別。

**收錄位置**:未完成處理之來源留在 `Inbox/`;完成處理後依第七章儲存流向轉入 `DOC/Stocks/`、`DOC/Archive/` 或 `DOC/Review/`,並同步更新 `DOC/INDEX.md`。入口淘汰與已完成回填的一次性素材仍依本節直接棄置,不得因設有 Archive 而保存。

### 2.6 背景模塊(r1 新增)

**動機**:量多、不主要、但缺了就難談論的內容——鋪陳、業界脈絡、人物軼事。實證:SRC-002 的 M14(作者三年軌跡)為技能訊號否,卻是演講稿的最佳開場鉤。二值制無法區分「行銷垃圾」與「撐場面的背景」。

**標記方式**:不動模塊核心欄位(避免破壞性變更)。於語義角色清單增列值「背景」(background);技能訊號維持否。

**判準(給抽取器)**:命題對至少一個技能訊號模塊構成動機、伏筆或情境支撐,但自身無程序、無可遷移主張者,標背景;連支撐都不構成者,為純填充。

**消費規則四條**:

1. **不進對齊**:背景模塊不進對齊操作,故不產生亦不影響任何登記層狀態(含熟練度);其素材使用不計入語義評分。
2. **渲染層可讀**:講稿與投影片生成時,允許取用與鏈端點有邊相連之背景模塊的正文與素材。4.2a 原「放寬條款」由此轉正——開場鉤的家本來就是背景模塊。
3. **可當邊的端點,不可當圖式主體**:背景常為動機邊與伏筆邊的來源,禁其上邊會丟失真實結構;但不得入鏈、不得當星形樞紐、不得被拔點——圖式抽樣時背景節點視同不存在。
4. **問答中只作題幹語境,不作考點**:「作者用某軼事鋪陳了什麼主張」合法(考點是被鋪陳的主張);「該軼事的細節為何」不合法(考背景本身,無技能價值)。

**一句話定位**:背景是舞台,不是演員——渲染時要它,計分時無它。
