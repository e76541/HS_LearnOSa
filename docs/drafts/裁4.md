# 裁4 · LEARN 補到什麼程度才返回 WORK

- 狀態：待裁
- 主幹：D48（WORK／LEARN／VERIFY）
- 優先：P2（D49）
- 關聯：`裁1`（WORK→LEARN 入口路由的上游）
- 歷史關聯：`裁3`、Q2、B-9 為舊補知／計點／場次語境；依 D49 已降為背景，不再決定本案主幹
- 關聯圖：舊 `2026-07-27-裁1-3-關聯子圖.html` 僅歷史參照；D48 現行主幹關係為 `裁1 → 裁4`
- 建議落點：若裁決通過，回寫 D48 的 LEARN→WORK 返回條件，並同步 D38 `L1-05 返回` 定義

## 0. 重寫說明

本案原題為「卡點填補四洞怎麼補」，一次處理材料種類、補完認定、失敗計數與場次紀錄。該題混合了主流程、量測與紀錄問題。

D48／REBUILD1 已經把責任重新分開：

- **L3-02** 負責依卡點組最小材料。
- **LEARN** 只補到能繼續，不要求學完整領域。
- **WORK** 才負責真實任務的執行與驗收。
- 熟練度／計點不屬 LEARN 主幹。

因此裁4保留真正阻塞主線的一題：

> **進入 LEARN 後，補到什麼程度就必須返回原 WORK 節點重試？**

本案只裁**返回協議**；不裁材料固定格式、熟練度、跨趟狀態或正式內容驗證。

---

## 1. 邊界先固定

### 1.1 LEARN 不負責證明「已學會」

LEARN 的任務不是建立一個完整能力評分器，而是針對當前卡點提供最小修補。

因此：

- 不要求把整個模塊學完。
- 不要求達到熟練度門檻。
- 不要求先通過一套獨立考試才准回 WORK。
- 不把 LEARN 的局部練習結果當成 WORK 任務完成。

### 1.2 WORK 才是真實驗收場所

真正重要的是原來那個 WORK 節點是否能繼續。

所以返回後必須：

1. 回到**同一個原 WORK 節點**。
2. 用剛補的能力重新執行／判斷一次。
3. 由 WORK 的原需求／完成條件判斷是否真的前進。

若重試仍失敗，再重新分類原因：

- 還是人的能力缺口 → 可再次進 LEARN。
- 其實是工具／來源／整合問題 → 依裁1回 WORK 排錯。
- 已產生正式主張／採用問題 → 另進 VERIFY；不由 LEARN 代判。

---

## 2. 要裁的問題

> **LEARN 的退出條件應是「已具備足以重試原 WORK 節點的最小可執行能力」，還是「先在 LEARN 內通過額外驗收，再返回 WORK」？**

---

## 3. 選項 A — 可重試即返回；成不成功交回 WORK

### 做法

LEARN 只要產生一個**足以讓人重新執行原節點的最小可執行單位**，就立即 `L1-05 返回`。

「足以重試」至少具備：

1. **原節點明確**：知道要回哪一個 WORK 節點。
2. **下一動作／判斷明確**：知道回去要做什麼，或要依什麼條件作判斷。
3. **必要材料可用**：本輪 L3-02 所需的最小材料已取得；若材料本身不存在，應退出 LEARN 回 WORK，不算補完。

流程：

```text
WORK 原節點
→ 裁1 判為人的能力缺口
→ LEARN:L1-02
→ L3-01 查資源
→ L3-02 組最小材料
→ L1-04 局部導航／跟讀／練習
→ 已能說清／執行「回原節點後下一步怎麼做」
→ L1-05 立即返回
→ WORK 原節點重試
→ WORK 驗收／重新分類
```

LEARN 不先替 WORK 判定「這次一定會成功」。

### 優點

- 和 D48「LEARN 是局部支線」完全一致。
- 不需要新造學習評分器或熟練度 Gate。
- 真實能力直接在原任務情境中驗證，避免練習題通過但真實任務仍失敗。
- 失敗時可重新路由，不會把 LEARN 變成無限補課。

### 缺點

- 可能較常發生「返回 WORK → 還是卡 → 再進 LEARN」的小迴圈。
- 「已能重試」仍有少量人為判斷，但它只決定是否回原節點，不宣稱已掌握。

---

## 4. 選項 B — LEARN 內先通過局部驗收，再返回 WORK

### 做法

在 L1-04 後增加一個 LEARN 內部 Gate；只有通過與原卡點對應的題目／模擬／判斷測試，才允許 L1-05 返回 WORK。

流程：

```text
LEARN 局部路徑
→ LEARN 內部驗收
   ├─ 通過 → 返回 WORK
   └─ 未通過 → 留在 LEARN 繼續補
```

### 優點

- 可減少明知還不會就過早返回 WORK 的情況。
- 對有明確標準答案的技能，局部練習可能提供額外訊號。

### 缺點

- 必須定義「通過」；專案型、策略判斷型卡點未必有答案卷。
- 容易重新引入熟練度／評分器，與 D38「導航只產事件、不寫熟練度」衝突。
- 可能把原本應由 WORK 真實驗收的責任搬回 LEARN，形成兩套 Gate。
- 一旦內部 Gate 失準，LEARN 可能無限停留，違反「補最小後返回」原則。

---

## 5. Agent 建議

- 建議選：**A — 可重試即返回；成不成功交回 WORK**。
- 前提：WORK 原節點必須有可辨識的下一動作或最低完成條件；若原 WORK 本身沒有任何可驗收目標，應先回 WORK 把目標補清楚，而不是要求 LEARN 代造驗收標準。

理由：

> D48 已把「做事」與「學習」分層。LEARN 最合理的出口不是證明人已學會，而是恢復執行能力；真正是否有效，直接回原 WORK 節點測最準。

---

## 6. 返回後的三種結果

採 A 時，返回 WORK 後只看真實結果：

| 返回結果 | 下一步 |
|---|---|
| 原節點成功前進 | 留 WORK 繼續主流程 |
| 原節點仍卡，且仍屬人的能力缺口 | 可再進 LEARN，針對新暴露的最小缺口修補 |
| 原節點仍卡，但發現是來源／工具／整合／能力供給問題 | 依裁1留 WORK 排錯／替換，不得用更多 LEARN 掩蓋 |

若任務結果已足以形成「是否採用／是否支持主張」的正式判斷需求，再由 WORK 另呼叫 VERIFY；**WORK 任務驗收 ≠ VERIFY 內容驗證**。

---

## 7. 舊四洞重新處置

| 舊洞 | D48 後處置 |
|---|---|
| ① 補的材料是什麼 | **退出裁4**；由 `L3-02` 依卡點組最小材料，不固定原文重讀／題型 |
| ② 補完怎麼認定 | **保留為裁4核心**；改成「已足以返回原 WORK 節點重試」 |
| ③ 失敗幾次記一次不懂 | **移出主幹**；若未來需要 telemetry／叫停，再另議，不阻塞返回 |
| ④ 場次怎麼記 | **降為最小事件紀錄**；不作返回 Gate |

### 最小事件紀錄（非裁決 Gate）

若系統要留事件，只需能追溯：

- `work_node`：原 WORK 節點。
- `learn_gap`：本輪補的最小能力／判斷缺口。
- `material_ref`：本輪實際調用的材料／資源引用（若有）。
- `retry_result`：回 WORK 後「前進／仍卡／改判外部缺口」。

不要求累積分數，不要求跨趟繼承，不把紀錄本身當真值。

## 8. 與裁1的接縫

裁1與裁4只各負責一半：

```text
裁1：這個失敗要不要進 LEARN？
                 ↓
              LEARN
                 ↓
裁4：什麼時候必須回 WORK 重試？
```

- 裁1不決定怎麼補。
- 裁4不重新判斷最初為何進 LEARN。
- 若 LEARN 中途發現最初分類錯了，可立即退出回 WORK，這是**路由修正**，不是「學習失敗」。

---

## 9. 與 D38／D48 的一致性檢查

### D48

- 符合「LEARN 在能力不足時局部補足並返回」。
- 不把 WORK 任務驗收搬進 LEARN。
- 不侵入 VERIFY 的證據／結論權限。

### D38

- `L3-02` 繼續負責組最小材料，裁4不固定材料型態。
- `L1-04` 繼續是局部路徑。
- `L1-05` 被明確化為「足以重試即返回」，而不是「達到熟練度再返回」。
- 導航仍只產事件，不寫熟練度。

### 裁2／裁3

- 裁2跨趟狀態不影響本輪是否返回。
- 裁3熟練度點數不作返回條件。

因此裁4完成重寫後，第一輪 `WORK → LEARN → WORK` 已有完整入口題與出口題；**兩案仍各自待裁，重寫完成不等於裁決完成。**

---

## 10. 全案風險

- 若選 A 但 WORK 節點本身定義太模糊，會出現「回去也不知道怎麼測」；這應修 WORK 目標，不應用 LEARN Gate 補洞。
- 若選 B，最主要風險是重新造一套學習驗收／熟練度系統，讓 LEARN 從局部支線膨脹成主流程。
- 無論 A／B，都不能把來源／工具本身不存在的問題留在 LEARN 無限處理。
