# 待裁草案列表

本檔為**治理**待裁／已裁總表，並為待裁**義務與用語真相**（AGENTS 只留詞彙指針，不重複細則）。  
單案正文見同目錄 `裁{n}.md`。輕量一句待決仍可寫「討論結論」；**同一件事禁止兩邊各寫正文**（討論結論只准留「見裁{n}」指針）。

裁號格式：`裁{n}`（與作業模塊 ID、成品 `C{n}`、站位分開）。  
僅當有選項爭議、需寫風險、會牽連他案、或之後要引用時才開號。  
**裁號即本系草案短代號**；領域 specs／plans 另用 `D{n}`（見 [草案短代號](../reference/terms/草案短代號.md)、[docs/INDEX.md](../INDEX.md)）。凡草案必有短代號。

**分流（本專案）**：

| 入口 | 管什麼 | 短代號 |
|---|---|---|
| 本檔 `docs/drafts/` | 治理完整待裁（啟用作業模塊、規範級提案等） | `裁{n}` |
| `docs/INDEX.md` | 領域規格／計畫草案狀態 | `D{n}` |
| 「路線」 | 執行真值上的待裁／阻塞 | `INI-*`／`ADJ-*`（路線號，非草案短代號） |

## 用語

| 術語 | 意義 |
|---|---|
| 裁號 | `裁{n}`；單案檔 `裁{n}.md` |
| 待裁／已裁／撤回 | 已裁≠已升格／已啟用 |
| 後續動作 | 僅備忘／提案升格／提案啟用／改路線或看板／開派生裁／撤回；至少勾一項才得標已裁 |
| 選項建議 | 預設恰 A／B（軟上限 2）；必有做法；優缺選填；Agent 建議＋前提（前提選填）；加 C 起先問使用者 |
| 翻案 | 已裁不得改採納；新開裁號、關聯舊號、寫相對變更 |

## Agent 義務

1. 詞彙／指令「待裁」→ 以本表列出待裁。
2. **展開格式**（依序）：①要裁的問題 ②選項 A／B（做法；優缺有才列）③Agent 建議＋前提 ④全案風險 ⑤若有關聯子圖則附連結。
3. 選項軟上限 **2**；要加第 3 個起 → 先提示使用者，同意再寫入。
4. 標已裁：須勾後續動作並記採納選項；採納↔後續動作明顯矛盾 → 回報請改、不自動改；末尾可提示選填否決理由（不強制）。
5. **翻案**：已裁不得改採納選項；改裁＝新開裁號、關聯舊號、寫明相對舊裁變更了什麼。
6. 本輪 ≥2 裁號且存在關聯邊、且未標 `免` → 只畫本輪子圖（需 T／archify；產出放本目錄、變更列作業模塊欄 `—`；失敗則 Mermaid，不得假完成）。
7. **不做**：投票／權重、優缺最低條數、預估時數（排期且使用者點名除外）。
