# 裁1 · WORK 卡住時，何時切入 LEARN

- 狀態：待裁
- 主幹：D48（WORK／LEARN／VERIFY）
- 優先：P1（D49）
- 關聯：`裁4`（LEARN 補足後如何返回 WORK 的下游）
- 歷史關聯：`裁2`、`裁3` 原依附舊空位／卡點語境；依 D49 已後置，不再阻塞本案
- 關聯圖：舊 `2026-07-27-裁1-3-關聯子圖.html` 僅歷史參照，不代表 D48 新關係
- 建議落點：若裁決通過，回寫 D48 的 WORK→LEARN 切換條件，並在 D38 明示 L1-02 只處理已進入 LEARN 後的能力／判斷卡點

## 0. 重寫說明

本案原題為「原文寫一半，算空位還是卡點」。該題建立在舊文本導航框架，判準依賴「能不能出題／文字有沒有出現」。

D48 已把最外層改成 WORK，LEARN 只在**人的能力不足**時局部介入，因此裁1保留「缺口分類」核心，但改裁更上位的路由問題：

> **WORK 卡住時，什麼情況應留在 WORK 排錯／補資源，什麼情況才應切入 LEARN？**

本案只裁**入口路由**；不裁 LEARN 裡怎麼補、怎麼返回（裁4），也不裁跨趟狀態（裁2）或熟練度計點（裁3）。

---

## 1. 邊界先固定

### 1.1 WORK 管什麼

WORK 負責把事情做成，包括：

- 輸入／來源缺失。
- 工具、API、權限、環境故障。
- 工具之間無法整合或組合失敗。
- 根本沒有符合需求的現成能力，需要找替代方案或新增能力。
- 執行結果不符合任務驗收，需要排錯、替換或調整。

以上問題即使「人現在不知道怎麼解」，也不能只因不知道就自動視為 LEARN；先看阻塞本體是不是外部執行條件不足。

### 1.2 LEARN 管什麼

LEARN 只處理：

> **完成當前步驟所需的來源／工具／能力客觀上已存在且可用，但人缺少足以繼續的操作、理解或判斷能力。**

典型情況：

- 工具正常，但不知道怎麼操作。
- 材料存在，但看不懂必要部分。
- 已有候選方案與必要資訊，但不會做當下的策略判斷。
- 已有可執行流程，但某個前置能力不足，導致無法完成該節點。

進入 LEARN 後才走 D38／RBF1 的 `L1-02 → L3-01 → L3-02 → L1-04 → L1-05`。

### 1.3 VERIFY 不由本案代替

如果問題不是「怎麼做」，而是：

- 這個結果能不能支持某個主張；
- 方案是否值得採用；
- 是否能形成正式對外判斷；

則依 D48 轉 VERIFY（D32～D34），不是因為有不確定就送進 LEARN。

## 2. 要裁的問題

當 WORK 在某個節點無法繼續，而且一開始不確定問題究竟出在人、工具、來源還是能力供給時，WORK→LEARN 的入口要採哪種路由？

---

## 3. 選項 A — 先做最小診斷，再把「人的能力缺口」送進 LEARN

### 做法

使用以下三段判準：

```text
WORK 卡住
↓
① 當前步驟的必要外部條件是否存在且可用？
   - 輸入／來源有沒有？
   - 工具／API／權限／環境能不能用？
   - 所需能力／服務是否客觀存在？

   否 → 留在 WORK：補輸入、找來源、修工具、換方案、補能力供給
   是 → 進②

② 已有條件足以讓這一步成立，只是人不會操作／理解／判斷嗎？

   是 → 切入 LEARN
   否／仍不清楚 → 進③

③ 在 WORK 做一次最小診斷嘗試，只為取得阻塞證據

   觀察到外部故障／缺資源 → WORK
   觀察到條件正常但人無法完成 → LEARN
```

### 特殊情況

- **來源本身沒寫必要資訊**：屬 WORK 的來源／資源缺口；先補來源，不叫人反覆學不存在的內容。
- **來源存在，但 L2 尚未切模塊／抽邊**：這不是「能力不存在」；進 LEARN 後依 RBF1 先跑 SK-02／03 備料，再走 L3。
- **工具存在且正常，但不知道怎麼用**：LEARN。
- **工具存在但壞掉、權限不足、API 不相容**：WORK。
- **不知道該選哪個方案，但必要資訊已在手上，缺的是判斷方法**：LEARN；若要形成正式採用結論，再另外進 VERIFY。
- **不知道該選哪個方案，因為必要資料根本沒有**：WORK 先補資料；不先用 LEARN 猜。

### 優點

- 與 D48 的責任邊界一致：WORK 排外部問題，LEARN 補人的能力。
- 可防止「工具壞掉＝我不會」「來源沒寫＝我沒學會」兩種誤診。
- 判不清時只要求一次最小診斷，不需要先做完整根因分析。
- LEARN 的入口因此有可核對依據，不會變成所有未知問題的垃圾桶。

### 缺點

- 比「一卡就學」多一個診斷動作。
- 若最小診斷定義失控，可能膨脹成完整 troubleshooting 流程。

### 限制

最小診斷只回答「阻塞主要落在外部條件還是人的能力」，**不是要求在入口就找出完整根因**。一旦取得足以路由的證據就停止診斷。

---

## 4. 選項 B — 只要人無法繼續，就先進 LEARN，再由 LEARN 內部分流

### 做法

```text
WORK 卡住
→ 只要當下不知道怎麼繼續，一律先進 LEARN
→ LEARN 查資料／工具／模塊
→ 若最後發現是工具或來源問題，再退回 WORK
```

### 優點

- 入口最簡單，不需先分類。
- 使用者主觀上只要承認「我卡住了」即可啟動處理。

### 缺點

- 工具故障、資料不存在、能力根本不存在，都會先被誤送進學習流程。
- LEARN 會被迫承擔 troubleshooting、資源搜尋、工具替換等 WORK 職責，破壞 D48 分層。
- 容易重現舊問題：對不存在的材料反覆補知，或把整合失敗誤診成學習不足。
- 返回點變得模糊：有些案件其實從未真正進入過「人的能力缺口」。

---

## 5. Agent 建議

- 建議選：**A**。
- 前提：把「最小診斷」嚴格限制為**一次取得路由證據的嘗試**，不得擴成完整排錯流程。

理由：D48 的價值就在於把「做事」「學習」「證據驗證」分開。若所有不知道都先進 LEARN，三者會再次混在一起；先辨認阻塞本體，才能讓 LEARN 維持「局部補能力後返回」的角色。

---

## 6. 與 D38 的一致性檢查

若選 A，D38 應解讀為：

```text
WORK
→ 裁1 路由確認＝人的能力／判斷缺口
→ 進 LEARN
→ L1-02 定位具體策略卡點
→ L3-01 查 L2
→ L3-02 組最小材料
→ L1-04 局部路徑
→ L1-05 返回 WORK
```

因此：

1. `L1-02` **不是** WORK 全域故障分類器；它只處理已進 LEARN 後的具體能力／策略卡點。
2. `L2 缺模塊／邊` 與「來源根本不存在」必須分開：前者可 SK-02／03 備料，後者留 WORK 補來源。
3. 裁4接在本案之後，只處理「已確定要學之後，補到什麼程度才返回」。
4. 裁2／裁3不影響這條第一輪路徑。

---

## 7. 全案風險

### 選 A 的主要風險

入口多了一次判斷，Agent 可能過度診斷。防線是：**只要能回答 WORK 還是 LEARN 就停止**，不要求入口解完問題。

### 選 B 的主要風險

LEARN 變成所有不確定性的預設入口，最終重新吸收 WORK 排錯與資源供給責任，等於把 D48 的分層取消。

### 不裁的風險

D48 可以畫出 WORK→LEARN 箭頭，但實際執行時沒有一致入口：同一個 API 故障、來源缺口或操作不熟，不同輪次可能被送到不同系統，後續試跑不可比較。

---

## 8. 裁決後預計動作

若採 A，建議：

- D48：補一段 WORK→LEARN 最小路由規則。
- D38：明示 L1-02 是 LEARN 內部卡點，不承擔 WORK 外部故障分類。
- 裁4：以前述入口為上游，重寫成 LEARN→WORK 補足／返回協議。
- 不因本案更動裁2／裁3的後置排序。

若採 B，則 D48 必須同步承認 LEARN 是預設 triage 入口；這會改變 D48 現有責任邊界，不能只改裁1單檔。
