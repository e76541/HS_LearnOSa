## 背景

目標管線改為以文檔為中心：

```text
批次收錄 → 文檔 YAML → 文檔保存／封存 → 模板化 → 正規化／模塊化 → 抽邊 → 下游學習產物
```

現行 DOC 儲存設計把 `DOC/Stocks`、`DOC/Archive` 與 `DOC/Review` 定義為模塊化、抽邊等必要處理完成後的出口。故不可直接把 `DOC/Archive` 挪作模板化前的封存位置，否則會混淆「已保存」與「已完成語意處理」。

## 提案決策

在模板化前設立窄責任的「文檔登記與保存層」（Document Registry and Preservation Layer）。它不是全域的收錄後處置狀態機，也不擁有模塊、邊或技能關係的真值。

| 記錄 | 擁有的真值 | 明確不擁有 |
|---|---|---|
| `BatchReceipt` | 一批何時、從何處收到哪些文檔 | 文檔身份與語意分類 |
| `DocumentManifest`（`document.yaml`） | 文檔身份、來源、內容指紋、修訂與保存參照 | 模塊、邊、技能、閱讀結論 |
| `PreservationEvent` | 保存／封存行為、目標與理由 | 模板產出與完成度 |
| `TemplateInstance` | 某文檔修訂採用的模板及其產出參照 | 文檔身份與保存決策 |
| 模塊與邊 | 文本語意與字元區間證據 | 收錄、保存或模板排程 |

## 不混同的兩個判斷

「保存／封存」與「是否進入模板化」必須分開記錄。

- 保存／封存回答：原始與正規化內容是否可靠保留、可從哪裡取回。
- 模板化回答：哪個文檔修訂、用哪個模板版本、何時進入處理。

因此，封存文檔不必等於永不模板化；若日後需要，可建立新的 `TemplateInstance`，而不是搬移資料夾或改寫文檔身份。

## 最小資料模型

第一輪不新增正式 lifecycle enum 或轉移表；先以實際批次資料驗證欄位與工作流。

```yaml
# batch.yaml（每批一份）
batch_id: BATCH-...
received_at: ...
source_channel: ...
document_ids: []

# document.yaml（每個文檔一份）
document_id: DOC-...
received_in: []
origin: {}
content:
  raw_sha256: ...
  normalized_sha256: ...
storage_refs: {}
```

保存裁決與模板請求屬可追溯事件，不覆寫上述身份資料。第一輪可共置在同一文檔資料夾，但須以事件附加方式記錄，並保留 `document_id` 與內容修訂參照。

## 不變條件

1. 下游資產以 `document_id` 與內容修訂／指紋參照，不以資料夾路徑作身份。
2. 同內容重複收錄時，保留多筆批次收據，但不產生互相矛盾的文檔身份。
3. 原始內容變更不得在相同內容指紋下覆寫；須建立可辨識的修訂關係。
4. 敏感資訊檢查必須先於 YAML、原文或正規化副本進入版本庫；事後 sidecar 掃描不足以構成防線。
5. 模板化前不得寫入 `source.md`、`modules.md`、`edges.md`、技能登記簿或 `DOC/INDEX.md` 的完成性宣告。

## 儲存策略

建議使用穩定的文檔儲存根；實體資料夾位置只是保存實作，分類頁面與索引是投影。這可避免封存或搬移後使下游連結失效。

在完成遷移決策前，現有 `DOC/Stocks`、`DOC/Archive`、`DOC/Review` 維持既有的「處理完成後」語意。新層不得借用 `DOC/Archive` 名稱或路徑來表示模板化前封存。

## 試行範圍

1. 選一個既有實際批次，建立一份 `BatchReceipt` 與對應的 `DocumentManifest` shadow 資料。
2. 驗證批次—文檔對應、內容指紋、重複收錄與保存參照；不遷移既有 DOC 資料夾。
3. 為模板化建立只讀輸入契約，記錄模板 ID／版本與目標文檔修訂；不產生正式模塊與邊。
4. 由試行資料確認封存語意、實際路徑與模板輸出後，再提議 canonical、`ingest-text` Skill 與 DOC 儲存設計的修訂。

## 待裁決事項

1. 「封存」是否僅代表冷保存，或代表預設暫停模板排程；建議採前者，排程另記。
2. 模板是否一律對每個文檔修訂建立獨立實例，以及是否允許同一修訂套用多個模板。
3. 文檔儲存根的實體位置、原始檔與正規化檔的保存格式，以及既有 Inbox／DOC 的遷移策略。
4. 累積足夠試行資料前，不固定保存或模板相關的 enum、狀態轉移與 canonical 名稱。

## 與既有試行的關係

`post-intake-disposition-trial` 保持為模板後／Review 側的 non-canonical 註記試行；不可升格或擴充為新的文檔身份與保存層。
