## 核心工作單位

| 標準名詞 | 定義 | 避免使用的別名 |
| --- | --- | --- |
| **LEARNOSA** | 承載文本、學習拆解、實作紀錄與複習的個人學習系統。 | LEARNOSA 評分法、LEARNOSA 評估模型 |
| **驗證項目** | 包含一個驗證問題、驗證等級、本項完成條件、驗證結果與判斷的正式工作單位。 | 卡、驗證卡、製作卡、使用卡 |
| **開發日誌** | 保存實作過程、卡點、當下想法與下一步，且本身沒有驗證等級的紀錄。 | L0、第四級驗證、探路卡 |
| **使用紀錄** | 使用優先學習迴路進入主迴路時的最低產物（五欄）；本身不是驗證項目。 | 使用卡 |
| **驗證問題** | 所有驗證等級共同使用的問題上位詞。 | 主題、介紹題 |
| **探路問題** | L1 用來判斷是否值得繼續投入方向的驗證問題。 | 決策問題、研究問題 |
| **決策問題** | L2 用來判斷特定對象與情境是否採用方案的驗證問題。 | 探路問題、研究問題 |
| **研究問題** | L3 用來檢驗主要主張與證據邊界的驗證問題。 | 決策問題、研究方向 |
| **驗證等級** | 依預定結論權限區分 L1、L2 與 L3 的層級。 | 工作量、難度、內容長度 |
| **等級底線** | 本標準為每個驗證等級固定的最低完成要求。 | 最小可驗證成果、最低工作量 |
| **本項完成條件** | 製作者在開始前為單一驗證項目設定、且不得低於等級底線的具體結案條件。 | 成功條件、事後門檻 |
| **驗證結果** | 驗證項目實際觀察到的內容與正式判斷。 | 發布內容、日誌進度 |
| **驗證物** | 讓他人核對驗證結果的具體材料。 | 發布物、三件套 |
| **成果形式** | Notebook、圖表、API 或應用程式等驗證物的分類標籤。 | 發布形式、內容類型 |

| **AI 技術** | 驗證問題本身以 AI 原理、工作流、工具調用或應用為對象的問題領域。 | 任何使用 AI 協助的題目 |
| **AI 評估** | 模型本身是驗證對象，或模型不確定性會影響結論時使用的驗證類型。 | AI／模型、AI 輔助 |
| **模型資訊** | 用來識別受測模型、版本、日期、介面與關鍵設定的條件紀錄。 | 模型類別、AI 標籤 |

## 驗證狀態

| 標準名詞 | 定義 | 避免使用的別名 |
| --- | --- | --- |
| **想法** | 驗證項目尚未開始實際執行的狀態。 | 待辦、草稿（未說明驗證生命週期時） |
| **驗證中** | 驗證已開始，但尚未達到等級底線並完成判斷的狀態。 | 已發布、部分完成 |
| **驗證完成** | 驗證項目已達到等級底線並作出相應判斷的狀態。 | 成功、發布完成 |
| **驗證中止** | 驗證已開始，但在取得該級最低所需結果前決定結束的狀態。 | 不再投入、證據不足 |
| **本次進展** | 開發日誌對當篇工作現況的文字摘要。 | 驗證狀態、結果／現狀 |

## L1 探路

| 標準名詞 | 定義 | 避免使用的別名 |
| --- | --- | --- |
| **L1 探路** | 取得足以對照觀察目標並決定下一輪投入方向之訊號的驗證等級。 | 簡易 L2、採用測試 |
| **探路判斷** | L1 從另開後續項目、換方向另開項目或不再投入中選出的投入方向結論。 | 探索判斷、採用判斷 |
| **觀察目標 Z** | L1 開始前宣告、用來界定本輪要觀察什麼的中性訊號。 | 成功答案、事後目標 |
| **可見結果** | 實際嘗試後產生、足以對照觀察目標 Z 並支持 L1 判斷的輸出。 | 心得、感覺、任意中間輸出 |
| **可核對阻礙** | 明確指出受阻步驟、實際錯誤或缺口及其影響的 L1 結果。 | 做不出來、資料不好找 |
| **另開後續項目** | L1 判斷目前方向值得再投入，並在當前項目結案後另開項目。 | 原項繼續、必定升級 L2 |
| **換方向另開項目** | L1 判斷目前方向不再投入，但另一方向值得另行驗證。 | 驗證中止、原地改題 |
| **不再投入** | L1 判斷目前沒有繼續驗證價值。 | 驗證中止、驗證失敗 |

## L2 決策驗證

| 標準名詞 | 定義 | 避免使用的別名 |
| --- | --- | --- |
| **L2 決策驗證** | 對特定對象與情境是否值得採用方案作出範圍有限判斷的驗證等級。 | 普遍性研究、快速試探 |
| **L2 決策判斷** | L2 從建議採用、有條件採用、暫時觀望、不建議採用與證據不足中選出的結論。 | 採用判斷、L3 行動判斷 |
| **建議採用** | 現有證據足以支持在本項宣告的對象、情境與限制內採用方案。 | 值得繼續、應該可以 |
| **有條件採用** | 只有在明列條件成立時才建議採用方案。 | 大致可用、有限支持 |
| **暫時觀望** | 現有證據足以判斷現在不宜採用，且已有明確重新評估條件。 | 證據不足、暫不作建議 |
| **不建議採用** | 現有證據足以判斷方案在既定情境中不值得採用。 | 失敗、沒用 |
| **證據不足** | 已完成 L2 預定驗證，但結果不足以作出前四種決策判斷。 | 驗證中止、暫時觀望 |

## L3 研究驗證

| 標準名詞 | 定義 | 避免使用的別名 |
| --- | --- | --- |
| **L3 研究驗證** | 以研究級證據檢驗主要主張及其結論邊界的驗證等級。 | 完整論文、專業認證 |
| **主要主張** | 接受 L3 證據判斷的主要候選答案。 | 研究問題、已證實結論 |
| **從屬主張** | 用來解釋主要主張、但不另需獨立方法或行動判斷的次要主張。 | 第二個主要問題 |
| **證據可行性檢查** | L3 啟動前對證據取得、追溯、區辨能力與資源界線所作的准入檢查。 | 完整研究報告 |
| **資料可行性檢查** | 數據型 L3 對資料涵蓋、來源、使用權與必要基準真值所作的追加檢查。 | 資料可行性門、所有 L3 必填資料欄位 |
| **證據判斷** | L3 對主要主張作出的支持、條件支持、不支持或無法判定。 | 行動判斷、採用建議 |
| **支持** | 證據足以檢驗主要主張，且在原定範圍內達到事前支持標準。 | 證明、普遍成立 |
| **條件支持** | 證據足夠，但主要主張只在事前宣告的條件或子群中成立。 | 事後挑選、部分成功 |
| **不支持** | 證據足以檢驗主要主張，但未達支持標準或結果與主張相反。 | 證明相反、無法判定 |
| **無法判定** | 證據、方法或可比較條件不足，無法合理區分支持與不支持。 | 不支持、暫不作建議 |
| **行動判斷** | L3 在相同對象與情境下，綜合證據、成本、風險與替代方案形成的實務方向。 | 證據判斷、L2 決策判斷 |
| **暫不作建議** | 證據、必要資訊或專業把關不足，因而不提出行動方向。 | 暫時觀望、無法判定 |
| **行動判斷不適用** | L3 研究問題不包含採用或實務行動時使用的欄位適用性標記。 | 第六種行動判斷、暫不作建議 |
| **外部可靠性主張** | 宣稱方法、基準、工具或資料成果具有足以讓外部使用者依賴之可靠性或有效性的 L3 觸發條件。 | 可重用成果、正式方法成果 |

| --- | --- | --- |

| **評估依據** | 從文本、架構、領域標準或本項需求取得並轉成可核對判定方式的準則。 | LEARNOSA 評估、個人感覺 |

| **代理指標** | 無法取得理想指標時，用來間接代表同一決策面向且須揭露限制的指標。 | 零分、等價指標 |
| **可追溯資料** | 來源、定義、取得方式與產生條件可以被查明的資料。 | 官方資料、免費資料 |

## 重大實務建議與專業把關

| 標準名詞 | 定義 | 避免使用的別名 |
| --- | --- | --- |
| **重大實務建議** | 直接支持真實行動，且錯誤可能造成明顯資金、產能、營運、安全、法規或權益後果的建議。 | 高成本專業行動、任何專業題目 |
| **專業把關** | 由具相關實務能力且不是製作者本人者，檢查重大實務建議之方法、邊界、風險與最終版本的程序。 | 外部審查、同儕審查、自我檢查 |
| **把關狀態** | 表示專業把關為不適用、未完成或已完成的欄位。 | 把關結果 |
| **把關結果** | 專業把關完成後記錄通過、有條件通過或未通過的結論。 | 把關狀態、證據判斷 |

## 後續與重驗

| 標準名詞 | 定義 | 避免使用的別名 |
| --- | --- | --- |
| **來源項目** | 被後續驗證項目引用的一個或多個既有驗證項目。 | 父卡、舊版本 |
| **後續項目** | 引用來源項目並建立自己問題、等級與結果的新驗證項目。 | 子卡、原項擴充 |
| **主要關係** | 每個後續項目從延伸、升級、轉向或重驗中選出的單一關係。 | 狀態、標籤集合 |
| **延伸** | 由既有結果產生新的驗證問題。 | 原地補功能、升級 |
| **升級** | 保留核心問題並提高驗證等級。 | 原項加欄位、延伸 |
| **轉向** | 不再投入原方向並改問另一個驗證問題。 | 驗證中止、原地改題 |
| **重驗** | 原結論出現重大疑點後，在相同核心問題下重新驗證。 | 修正項目、必定提高等級 |
| **結論待重驗** | 原結論出現重大疑點後加在原內容上的提示；若重驗仍不足以支持或推翻原判斷，提示繼續保留。 | 驗證中止、已被修正 |
| **重驗後維持原判斷** | 重驗支持原判斷後留下的結果標記。 | 已被修正 |
| **已被修正** | 重驗確認原判斷有實質錯誤後加在原內容上的關係標記。 | 驗證狀態、發布狀態 |

## 關係

- 一個 **驗證項目** 只有一個主要 **驗證問題** 與一個 **驗證等級**。
- **等級底線** 由標準固定，**本項完成條件** 由製作者在開始前設定。
- 一篇 **開發日誌** 可以關聯零至多個 **驗證項目**，但不因此取得驗證等級。
- **L1 探路** 產生一個可見結果或可核對阻礙，以及一個 **探路判斷**。
- **可核對阻礙** 只會依 L1 底線構成完成結果；L2 與 L3 單有阻礙不會自動完成。
- **L2 決策驗證** 產生一個 **L2 決策判斷**。
- **L3 研究驗證** 一定產生 **證據判斷**，只在有行動問題時產生 **行動判斷**。
- 數據型 **L3 研究驗證** 在 **證據可行性檢查** 外，還要完成 **資料可行性檢查**。
- 一個 **後續項目** 可以引用一至多個 **來源項目**，但只選一個 **主要關係**。
- 同時看似 **升級** 與 **重驗** 時，為覆核重大疑點選 **重驗**；沒有重大疑點、只提高嚴謹度才選 **升級**。
- **發布狀態** 屬於每份 **發布內容**，不屬於 **驗證項目**。
- 同一份 **發布內容** 可以同時是 **開發日誌** 與 **驗證報告**，相同資訊不必重寫。
- **重大實務建議** 必須使用 L3 並完成 **專業把關**，否則行動判斷只能是暫不作建議。
- 重驗未能支持或推翻原判斷時，原內容保留 **結論待重驗**，重驗項目的判斷不取代也不恢復原判斷。

## 對話示例

> **製作者：**「我今天把 Statcast 查詢接起來並貼出錯誤紀錄，這篇算 L1 嗎？」
>
> **規範維護者：**「如果只是保存過程，它是 **開發日誌**；只有你事前設定 **觀察目標 Z**，準備判斷是否繼續投入時，才建立 **L1 探路** 的 **驗證項目**。」
>
> **製作者：**「L1 得到圖表後，可以直接建議大家採用這個資料源嗎？」
>
> **規範維護者：**「不行；採用問題需要 **L2 決策驗證**，若再宣稱方法足以讓外部依賴，就命中 **外部可靠性主張**，最低要用 **L3 研究驗證**。」
>
> **製作者：**「我只想發開發日誌，還要另寫一篇驗證報告嗎？」
>
> **規範維護者：**「不用；同一份 **發布內容** 可以同時標成 **開發日誌** 與 **驗證報告**，正式判斷仍以關聯的 **驗證項目** 為準。」

## 已標記的歧義

- 「卡」曾預設看板或應用程式實作，正式工作單位統一稱 **驗證項目**；學習迴路產物稱 **使用紀錄**（禁用「使用卡」）。
- 「開發日誌」與 L1 曾重疊；只保存過程是 **開發日誌**，事前設定觀察目標並準備作投入判斷才是 **L1 探路**。
- 「想看到 Z」像成功目標，現統一稱 **觀察目標 Z**，可由可見結果或可核對阻礙完成。
- 「最小可驗證成果」曾混指各級最低要求，現拆成標準制定的 **等級底線** 與製作者制定的 **本項完成條件**。
- 「驗證結果」曾同時指發布內容與日誌現況，現只保留給正式觀察與判斷；發布類型稱 **驗證報告**，日誌欄位稱 **本次進展**。
- 「採用判斷」曾與 L3 行動判斷重疊，現改稱 **L2 決策判斷**；L3 分開使用 **證據判斷** 與 **行動判斷**。
- 「暫時觀望」「證據不足」「暫不作建議」曾混用，三者分別代表現在不採用、L2 無法決策與 L3 無資格提出行動方向。
- 「驗證完成」與「發布」曾綁在一起，現由 **驗證狀態** 與每份內容的 **發布狀態** 分開表示。
- 「AI」曾因任何輔助使用而成為泛濫分類，現只有問題本身在問 AI 時使用 **AI 技術**，只有模型是受測對象時套用 **AI 評估**。
- 「官方資料」曾被用來泛稱可靠或免費資料，現只指權責機構正式發布或授權的資料。
- 「LEARNOSA 評估」曾暗示固定評分表，現統一使用依文本、架構或需求取得的 **評估依據**。
- 「修正項目」預設原結論有錯，現改稱 **重驗**，結果可以維持原判斷或確認修正。
- 「發布形式」與內容角色曾混用，現由 **內容類型** 表示角色、**發布形式** 表示載體。
