# 文檔整合抽取與策略多樣性

- 狀態：草稿
- 裁決來源：無
- 實作參照：無
- 後繼：無（獨立草案；**不併入**來源學習排程／OSA／F3a 現行稿正文）

## 0. 定位

描述如何把**文檔資料庫**裡的材料，經整合抽取後，在策劃與決策現場以**可追溯來源**的方式供用，並保留多種抽取／取用策略。

- **不是** canonical、**不是** 路線 INI、**不是** 作業模塊啟用提案。
- **不是** 來源佇列本體（見 [來源學習排程](2026-08-05-source-learning-schedule.md)）、**不是** 導航站位規則（見 [F3a 現行稿](2026-08-05-f3a-navigation-current.md)）。
- 本稿核心是 **Gemini 輪詢**（兩功能，見 §2.1）＋決策點出示來源；未裁前以草案／試作名義討論，不改 `Library/規範`、不新開站位或作業模塊 ID。

## 1. 目標

| 目標 | 一句話 |
|---|---|
| 新訊入庫 | 輪詢持續**整理新訊息**，庫不靠人工一篇篇補 |
| 策略點提示 | 使用者調用，或**自動在策略點**給出提示（附來源） |
| 決策可溯 | 決策點必須顯示所用文檔與來源指標，禁止無來源斷言 |
| 策略多樣 | 抽取與取用不綁死單一打法，可依情境換策略 |

## 2. 流程總覽

```text
新訊息／庫變更
    → Gemini 輪詢【功能1：整理新訊息】→ 可檢索庫紀錄
                ↓
使用者調用  或  自動抵達策略點
    → 輪詢【功能2：給予提示】→ 提示＋來源指標
                ↓
決策點 → 顯示結論＋文檔來源（可疊加策略 S1～S6）
```

### 2.1 輪詢的兩項功能（Gemini）

**Gemini** 為固定輪詢者（本稿指定；更換須另裁）。輪詢**只有**下列兩功能，不得混成「順便決策」。

| 功能 | 名稱 | 觸發 | 做什麼 | 不做什麼 |
|---|---|---|---|---|
| **功能 1** | **整理新訊息** | 固定節奏輪詢（間隔待裁）；偵測新進／變更訊息與文檔 | 入庫或刷新可檢索紀錄：文檔 ID／路徑、輪詢時間、短摘要或索引鍵；可標用途／主題供後續策略用 | 不改寫原文真相檔；不當場給決策結論；結果不得只留對話暫存 |
| **功能 2** | **給予提示** | **(A) 使用者調用**，或 **(B) 自動在策略點** | 依當前問題／策略點上下文，從庫拉相關摘要／片段，輸出**提示**（建議關注什麼、可參考哪幾份、可選策略），且每條提示附來源指標 | 提示**不是**最終裁決；不得用過期對話記憶冒充庫內容；不得省略來源 |

#### 2.1.1 功能 1：整理新訊息

- 對象：文檔資料庫＋進入庫視野的新訊息（落點待裁，見 §5）。
- 產出最小欄位：文檔／訊息 ID、路徑或鍵、輪詢時間、短摘要或索引鍵。
- 可選：主題簇、用途標籤（對齊 S6），供功能 2 與策略選擇使用。
- 禁則：不把整理結果當 canonical；不刪原文。

#### 2.1.2 功能 2：給予提示（調用｜策略點自動）

| 觸發 | 說明 |
|---|---|
| **使用者調用** | 使用者明示要提示／要文件／要整理建議時執行 |
| **策略點自動** | 抵達已定義的**策略點**時自動觸發，無需再問一次「要不要拉庫」 |

**策略點**（草案封閉集，可待裁增刪）：

| 策略點 | 何時算抵達 | 自動提示至少包含 |
|---|---|---|
| **策劃點** | 規劃步驟、選路徑、組材料清單 | 相關文檔／訊息清單＋建議策略（如 S1／S3） |
| **需文件點** | 現場判定缺依據／缺原文 | 最小證據向提示（偏 S3）＋來源 |
| **決策點前** | 即將選定方案或裁定取捨前 | 提示＋來源；有爭議時加對照／反證向（S2／S5） |

提示輸出形狀（最小）：

1. **提示正文**（一句到數點，可執行或可核對）。
2. **來源清單**（可回查指標＋片段／摘要定位）。
3. **建議策略集合**（如 `S3` 或 `S3+S5`；可空，但決策點前建議不空）。

### 2.2 決策點：顯示結論與來源

決策點（選定方案、裁定取捨、輸出可執行下一步）必須同時具備：

1. **可見結論**（選了什麼／不選什麼）。
2. **文檔來源清單**：每條至少含可回查指標（路徑、文檔 ID、或庫內鍵）＋本次用到的片段或摘要定位。
3. **來源角色**（可選但建議）：支持／反證／背景——避免把背景材料寫成硬依據。

決策點可**承接**功能 2 在「決策點前」已給的提示，但結論仍須重列**實際採納**的來源，不得只寫「見上方提示」。

**禁止**：

- 決策點只給結論、不給來源。
- 以來源「很多」代替標明**實際用到的**來源。
- 用無法回查的口語指稱（「之前那篇」）代替指標。
- 把功能 2 的提示逕稱「已裁決」。

## 3. 策略多樣性

整合抽取不綁單一策略。功能 1 可產出多視角索引；功能 2 與決策出示時，依情境選策略（可並用，須標明本次採用哪些）。

| 策略 ID | 名稱 | 何時用 | 產出重點 |
|---|---|---|---|
| S1 | **主題聚合** | 同一主題多篇散落 | 主題簇＋代表文檔列表 |
| S2 | **對照／衝突面** | 決策前要看分歧 | 同意點／分歧點＋各自來源 |
| S3 | **最小證據包** | 只要能過門檻的依據 | 少量高相關片段＋來源 |
| S4 | **時間線整理** | 版本或事件先後影響決策 | 依時間排序的來源鏈 |
| S5 | **反證優先** | 高風險決策 | 先列反對／邊界文檔，再列支持 |
| S6 | **用途分流抽取** | 材料用途不同（知識／方法／決策／系統） | 按用途標籤的抽取結果（對齊使用迴路四用途說法，不複製其①～⑥） |

### 3.1 策略選擇規則（草案）

- 預設：策劃點提示用 **S1 或 S3**；決策點前至少開 **S3**，有明顯爭議時加 **S2 或 S5**。
- 同一次提示／決策可疊加策略，但輸出必須標 **策略集合**（例如 `S3+S5`）。
- 策略可增刪，新增須進本稿表並待裁；Agent 不得臨場發明未登記策略 ID 卻寫進正式產物。
