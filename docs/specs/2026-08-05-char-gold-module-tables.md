# 含金量字元製模塊與同分組表

- 短代號：D46
- 狀態：草稿
- 裁決來源：無
- 實作參照：無
- 後繼：無（自 [D39](2026-08-05-doc-integration-extraction-strategy.md)／導航交界**獨立**；先試作效果，不升格）

## 0. 定位

把「以當下文本定義的字元當含金量 → 做成**文本模塊** → 依規範落檔 → 同定義／同背景／同狀況另表繪製」從 D39 與既有導航交界中**抽出**成獨立草案，**先測效果**。

- **不是** canonical 改寫、**不是** 路線 INI、**不是** 作業模塊啟用提案。
- **不是** D39「知識塊」（知識塊≠模塊）；本稿目標是做出**合規文本模塊**。
- **不是** F3a／OSA 站位規則本體；可對照導航，但不改 GATE／STEP。
- 未裁前僅**草案＋試作**；正式模塊若寫入 `DOC/`，須另符合現行 [領域規範](../../Library/CURRENT.md)（模塊層等），失敗則停在試作紀錄。

## 1. 目標（先測）

| 目標 | 一句話 |
|---|---|
| 含金量切塊 | 以**當下文本自己定義**的字元量為含金量，據此製成模塊候選 |
| 規範落檔 | 成為模塊後，**依原本規範**記錄（欄位、證據、ID 等） |
| 同分組表 | 後續將**同定義、同背景、同狀況**者，**單獨繪製表格**（一組一表） |
| 先測效果 | 本輪只寫規則與試作路徑；效果不好可改草案，不硬升格 |

## 2. 三步流程

```text
當下文本 → 依其「字元定義」算含金量 → 切／併成模塊候選
        → 依 canonical／技能 寫成正式模塊紀錄
        → 同定義×同背景×同狀況 → 單獨一張表（可多表並列）
```

### 2.1 文本上：當下字元定義＝含金量 → 製成模塊

| 規則 | 說明 |
|---|---|
| **當下文本** | 以**目前正在處理的那份文本**為準，不拿別篇的字元尺度硬套 |
| **字元定義** | 該文本（或場次契約）**明示或可推出**的計量方式：算哪些字元、是否含空白／標記（細部待裁 a） |
| **含金量數** | 依上述定義計得的數值；用來決定切塊大小／是否成塊，**不是**股價或外部評分 |
| **製成模塊** | 達門檻的一段文字成為**模塊候選**，目標對齊領域「文本模塊」，不是 D39 知識塊 |

**禁止**：用與當下文本無關的固定全域字數，偷偷覆蓋該文本自己的定義；不得把含金量寫成投資／行情預測。

### 2.2 變成模塊後：依照原本規範紀錄

模塊候選要落成可引用的模塊時：

1. 依 [Library/CURRENT.md](../../Library/CURRENT.md) 指向的模塊層／證據等**現行規範**寫欄位與證據（`char_span` 等以規範為準）。
2. 走既有 Skill／站位習慣時，摘要標 **F2**（切模塊）；不新開作業模塊 ID。
3. 規範衝突 → **停止**並回報，不擅自改 canonical；試作產出只進試作紀錄。

### 2.3 後續：同定義×同背景×同狀況 → 單獨繪表

| 分組鍵 | 意義（草案） |
|---|---|
| **同定義** | 同一套字元／含金量定義（或同一契約版本） |
| **同背景** | 同一文本背景、場景或來源脈絡 |
| **同狀況** | 同一使用／決策狀況（如同一策略點類型、同一問題標的） |

- 三者皆同 → 歸入**同一組**，為該組**單獨繪製一張表**（欄位待裁 b：模塊 ID、含金量、摘要、來源 span 等）。
- 任一鍵不同 → **另表**，不合併進他組表（對齊「不同思路不硬捏」精神，但單位已是模塊）。
- 表是**後續整理產物**；可先手工／md 表試作，再談自動繪圖。

## 4. 試作怎麼跑（建議）

1. 選**一篇**當下文本，寫清該篇的字元／含金量定義。
2. 依含金量切出數個模塊候選 → 試寫合規模塊欄位（可只紙上或 Inbox／試作夾）。
3. 依同定義／同背景／同狀況拆成 **≥1 張表**，看是否好讀、好比。
4. 結果記 [試作紀錄](../experiments/INDEX.md)；**先看效果**再議是否升格或改門檻。
