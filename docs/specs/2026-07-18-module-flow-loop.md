## 流程總覽

```
原文 → 抽組件 → 組裝模塊(+邊) ⇄ 提問(探知識邊界;拆併回饋到組件)
                              → 挑選(以知帶新) → 成景(渲染時計算) → 九宮
                                                    ↑        ↓ 攝入期:拿答案版照圖講一輪(照雙階段草案)
                                                    │        ↓ 練習期:三層隨機(照雙階段草案)
                                                    └── 測驗 + 間隔重複(到期觸發回宮)
```

相對雙階段草案的變化:在「原文 → 組件 → 模塊 →(場景)→ 九宮」中間插入**提問**與**挑選**兩站,九宮之後接**測驗+間隔重複**形成循環;提問站拆併的細粒度落點為**組件**(見組件化草案 r1:本體唯讀,拆併走版本／引用)。管線固定句已與雙階段、組件化草案同批改寫(2026-07-19;r1 改「不跳儲存層」);整合圖見 [組件化草案附圖](assets/2026-07-19-module-pipeline-flow.html)。

## 四條銜接規則(2026-07-18 對話定案)

### 1. 提問站:讓知識邊界落在邊上,不落在模塊中間

提問的目的不是出考題,是探使用者的知識邊界,並回饋校準模塊粒度:

- 某模塊「一半會一半不會」→ 邊界穿過模塊中間 → **拆**,拆到組件粒度再重組(不改組件本體;見組件化草案),直到每塊要嘛整塊會、要嘛整塊不會。
- 連續多個全會的模塊且邊為強依賴 → 可**併**。
- 這是在既有模塊層切分上的二次校準(細粒度落點=組件),不是另一套切法;與領域規範模塊層規則的關係於升格時對齊。

**問法:前沿輪**(2026-07-18 補;取自 grilling / batch-grill-me 設計,轉寫不套原 skill):

- 每輪計算**前沿**=與已知模塊有邊相連的未知模塊;對前沿各出一題,**一輪一批**問完。
- 答對者轉已知、前沿外擴;答錯者停住,邊界即畫在該處。前沿空了,診斷結束。
- 題目內容出自原文(agent 自查,不憑空出題);「知不知道」只有使用者能答,不得代答。
- **不採**原 skill 的「每題附建議答案」——測知識不得先給答案;使用者答完後才依原文核對(接 explain-this 的禁自評、依原文給分)。

### 2. 挑選站:以知帶新

- 已知模塊先進宮,作為錨點。
- 挑「不知道」的模塊時,優先挑**與已知模塊有邊相連**者;邊即教學路徑(從已知格沿邊講到未知格)。
- 與已知無連線的模塊暫緩,待梯子搭到再入宮。

### 3. 排程:模塊記狀態,九宮面觸發;原面優先

- 複習計時器掛在**模塊**(格)上:測驗答得好排遠、答得爛排近(SM-2 式,粒度取模塊不取單卡)。
- 「回到九宮」觸發條件:一面九宮內**到期模塊數 ≥ 門檻(暫定 3)**,整面重練。
- 回宮時**用原面**——格位不變,保留空間記憶(位置感是九宮形式最值錢的部分)。
- 唯一重組時機:該面模塊經規則 1 拆併過、原面已對不上時,才重排。

### 4. 攝入期保留;提問站對陌生材料輕量化

- 全新材料第一輪照雙階段草案:拿答案版照圖講一圈建圖,人和圖互相校對。
- 此時提問站只輕量探先備知識,不細問(未學材料問了皆為不會,無信息量);自第二循環起提問站才是主閘門。

## 試作後引入的工程零件(備忘,2026-07-18)

來源 [mattpocock/skills](https://github.com/mattpocock/skills)(wayfinder / to-tickets;整套工作流**不搬**——與本專案治理帳本重疊,僅取零件)。本節不屬學習流程,是**本草案試作完成後**、作業模塊啟用拆實作時採用:

1. **引用帶標題,不用裸編號**:敘述文字引用 INI/ADJ/M-ID 時永遠帶名稱,編號只當括號內錨點;裸編號強迫每棒 agent 先查表才能開工(現行 ADJ-001~004 式寫法為反例)。
2. **垂直切片 + 一個 context window 粒度**:實作票切「窄而完整」的縱向路(一票打通所有層的一個 case,可獨立驗收),尺寸以「全新 agent session 讀完票面+相關檔後仍有餘裕做完並自驗」為準;切片間宣告阻塞關係供平行開工;大範圍機械改動例外走擴張—收縮(新舊並存→分批遷→刪舊)。
