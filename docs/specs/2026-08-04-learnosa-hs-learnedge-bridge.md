## 1. 全專案詞彙分流（查表規則）

同名異義時，先判**所屬系統**，再查下表；禁止自創混名（如「驗證卡模塊」「L1 站位」）。

| 詞 | 內容製作 | 領域管線 | 作業治理 |
|---|---|---|---|
| **驗證** | 內容驗證：驗證項目之觀察與判斷 | 管線驗證：V1 抽查 §5 度量 | V1 橫切，非必經站 |
| **L1/L2/L3** | **驗證等級** L1／L2／L3 | 深度 1/2/3（usage 草案）；鷹架三級；五層耗損 | — |
| **日誌** | **開發日誌**（內容產物，可發布） | — | **作業日誌**／日誌報告（`docs/logs/`，交接觸發） |
| **本次進展** | 開發日誌欄位；作業日誌同欄名 | — | 作業日誌欄位（對準共同語言） |
| **模塊** | 避免單說；指知識單元時跟領域 | **文本模塊** | **作業模塊** M0/F/T/R/V |
| **卡** | 禁用；工作單位用**驗證項目**；學習產物用**使用紀錄** | — | **更新說明**（舊稱更新卡）；目錄 `update-notes/` |
| **狀態** | 驗證狀態；發布狀態 | `retention`；DOC bucket | 看板：進行中／完成／阻塞 |
| **採用** | L2 決策判斷詞 | `claim_kind=advice` 進圖表述 | — |
| **評估** | **評估依據**（依文本／需求） | §5 三十篇基準 | — |

**Agent 規則**：談內容製作→讀共同語言；談收錄／模塊→讀 CURRENT；談交接／檢查→讀 agent-ops；跨層→查本表。

## 2. 核心對照

### 2.1 工作單位

| 共同語言 | 專案近義 | 對準 |
|---|---|---|
| LEARNOSA | HS_LearnEdge／HS_LearnOSa | 個人學習承載；非評分模型 |
| 驗證項目 | 看板卡、作業模塊 | 只稱驗證項目 |
| 使用紀錄 | 使用卡 | 只稱使用紀錄 |
| 更新說明 | 更新卡 | 治理四格確認表；路徑 `update-notes/` |
| 開發日誌 | `docs/logs` | 內容＝開發日誌；治理＝作業日誌 |
| 驗證等級 | 深度層、鷹架級 | 寫「驗證等級 Ln」 |
| 驗證結果 | 管線輸出、本次進展 | 只＝觀察＋正式判斷 |
| 驗證物 | Dynamic View、三件套 | 可核對材料；≠發布形式 |

### 2.2 狀態禁混

| 系統 | 狀態詞 | 不可混稱 |
|---|---|---|
| 內容 | 想法／驗證中／驗證完成／驗證中止 | 發布狀態、本次進展 |
| 內容 | 未發布／已發布 | 驗證狀態 |
| 領域 | retain／discard／needs_review | 驗證狀態 |
| 治理 | 進行中／完成／阻塞 | L1/L2/L3 |

判斷詞禁混：**暫時觀望**（L2）≠ **證據不足**（L2）≠ **暫不作建議**（L3）≠ **無法判定**（L3 證據）。

### 2.3 進圖互譯

| 共同語言 | 領域 | 規則 |
|---|---|---|
| L2 決策判斷 | `advice` | 保留建議＋適用範圍 |
| L3 主要主張 | `verifiable_claim`、AnalysisModule | 未核對≠已證實 |
| 重大實務建議 | 強 `advice`＋記憶禁項 | 把關未完成→暫不作建議 |
| 後續項目 | 新驗證項目 vs F2 新模塊 | 互引 ID；不原地擴寫 |

## 3. 銜接縫（只連線）

1. **上游**：發布內容→F1 入口三問→DOC；不因驗證完成跳過候選分流。
2. **中游**：判斷詞→`claim_kind`／適用範圍忠實表述。
3. **下游**：F3c／F4 仍 P8 封閉世界；鷹架三級≠驗證等級。
4. **橫切**：V1 可提案抽查「是否超出驗證等級允許判斷詞」；不擁有驗證等級。
5. **治理**：作業日誌可選【關聯驗證項目】；欄位【本次進展】對準共同語言。

## 4. 作業日誌 vs 開發日誌

| | 開發日誌 | 作業日誌 |
|---|---|---|
| 觸發 | 內容製作需要 | 工作指令「交接」 |
| 落點 | 內容產物（任意） | `docs/logs/` |
| 等級 | 無 | 無 |
| 可發布 | 是 | 否（內部現場紀錄） |
| 模板 | 標準附錄 A | agent-ops 第五節 |
| 關聯 | 可關聯驗證項目 | 可選關聯驗證項目 |

欄位名對準：兩者均用【本次進展】，不用【結果／現狀】。

## 5. 試跑最小協議

1. 先判開發日誌 vs 驗證項目。
2. 驗證項目：驗證等級、本項完成條件、驗證狀態；判斷詞用標準名詞。
3. 發布走標準 §11；交接才寫作業日誌。
4. 進學習系統＝來源文本；進圖用 §2.3，不把「判」洗成 ground truth。
5. 新問題→後續項目；新結構→F2。

## 6. 明確不做

- 不把驗證等級登記成作業模塊／站位。
- 不強制每則 DOC 先有驗證項目。
- 不恢復三件套必做。
- 不用共同語言禁詞（卡、使用卡、更新卡、L0、LEARNOSA 評估、結果／現狀）。
- 未試跑不升格 CURRENT／不開 v0.4。

## 7. 試跑後決策（2026-08-04）

見 [試作紀錄](../experiments/2026-08-04-learnosa-content-verification-trial.md)：

- **ingest 標記**：試跑期**不提案**新增 F1 硬欄位；內容來源可在 `DocumentManifest` 備註層以自由文字標「內容驗證來源」，待第二題試跑後再裁。
