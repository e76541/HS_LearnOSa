# 第一部｜前置文本：這套東西從哪裡來

導航模式不是憑空長出來的。它是六次轉向疊起來的結果，缺任何一層都會看不懂為什麼有那條規則。

## 一、目的轉向（來源：導航 OSA 決策牌組草案）

**舊的主流程**是：文本 → 模塊與邊 → 練習 → 熟練 → 演說。學完才能用。

**新的主流程**是：

```text
真實目的
→ 定位當前情境
→ 找出會改變路線的必要判斷
→ 使用者能判斷：直接選擇
→ 使用者不能判斷：診斷缺口 → 補最小知識 → 重新判斷
→ 選擇改變後續牌組
→ 執行下一步並回報結果
→ 重新定位
```

終點從「完成課程」改成「**使用者在真實任務中能作出有依據的選擇，並拿到可執行的下一步**」。學習沒有消失，但從主目的降為導航途中的按需能力形成。

這一句轉向決定了後面所有規則的形狀：既然不是課綱，就不能有固定站序；既然不是課綱，就必須有別的東西決定下一步該做什麼——那個東西後來就是「缺口」。

**刻意不做（來自同一份草案）**：不要求先學完課程才開始任務；不把固定課程順序改名為牌組；不由系統默默替使用者作高影響決定；不把一次情境生成的路徑回寫成通用知識真值。

## 二、三層模型（來源：導航 OSA 決策牌組草案）

```text
證據層                      決策投影層                    導航控制層
原文／模塊／邊         →     前置閘門＋引導＋方案比較   →   目的牌組＋目前位置＋分支
```

| 層 | 主要物件 | 責任 | 是不是真值 |
|---|---|---|---|
| **證據層** | 原文、模塊、模塊間的邊、字元區間 | 保存主張、方法、條件、案例與關係 | **是**。導航只讀，永不回寫 |
| **決策投影層** | 決策就緒檢查、引導、方案剖面、決策牌 | 先確認能不能決定，再把知識轉成「要考慮什麼、有哪些方案、選了會怎樣」 | 可重建的投影，不取代模塊 |
| **導航控制層** | 旅程、站、步紀錄、牌組、路線狀態、決策紀錄 | 依目的與實際結果動態組牌、重排下一步 | 場次狀態，不回灌證據層 |

**這一層的核心邊界，後面反覆用到**：

> 模塊不改成牌。模塊是牌的證據；決策牌是導航介面；牌組是情境生成的路徑。

## 三、證據層本身的規則（來源：領域規範，模塊層與結構層）

這一節是**領域規範**（canonical，已生效），不是草案。導航模式無權改動它，只能消費。

**模塊層的三條硬規則**：

1. **模塊是唯讀證據層，生成後不變，不承載任何流轉狀態。**狀態一律住登記層。
2. 模塊拆分由**命題簇**決定，不由段落或章節決定。不同簇之命題各有不同外部依賴目標，強制拆分。
3. 每個模塊帶字元區間，可回指原文。素材（故事、金句、公式）附屬於宿主模塊，不獨立成節點、不進邊層。

**結構層的四條硬規則**：

1. **禁設順序邊。**文本順序由字元區間線性層承載，不進邊圖——理由是資訊重複且會誘發全連接濫標。
2. 箭頭指向被支撐者（子指向父、後指向前）。這是**支撐方向**，不是敘述方向。
3. 章節帶是排版鷹架，**非承重結構**。無章節時降級為段落序列，再保底為字元區間線性順序。
4. 入邊數只是重要性的**代理指標**，禁止僅以入邊數自動決定資產提升；提升一律過人工關卡。

**這三條合起來，回答了一個關鍵問題**：文本順序、結構順序、導航順序是**三種不同的順序**，不能互相替代。詳見第三部開頭。

## 四、決策前置閘門與決策牌（來源：導航 OSA 決策牌組草案）

正式比較方案之前，先判斷「現在是否已具備作決定的條件」。這個檢查的頂層欄位固定，欄內細項依領域與情境生成：

| 欄位 | 中文 | 內容 |
|---|---|---|
| `decision_ready` | 是否可決定 | 是／否／強制 |
| `authority` | 權限 | 誰有權決定，權限邊界在哪 |
| `information_sources` | 資訊來源 | 現有資訊、來源與可信度 |
| `source_conflicts` | 來源衝突 | 來源之間的矛盾 |
| `unknowns` | 未知項 | 可能改變答案的未知 |
| `deadline` | 期限 | 最晚決定時間與逾時代價 |
| `can_wait` | 能否等待 | 能不能等補充資訊，等待成本多少 |

**固定的是頂層介面，不是萬用細項。**原文沒提供的內容標示「作者未提供」或「未知」，不得為填滿模板而補造。

**閘門只有三個出口**：

1. 資訊與權限足夠 → 展開考量與方案比較
2. 資訊不足但可等待 → 先查證，暫不作決定
3. 資訊不足且不能等待 → 強制風險決策，明示假設、監測訊號與退路

閘門的作用不是替使用者選，而是**避免系統回答一個尚不能可靠回答的問題**。

**同一張決策牌內有兩種可重用投影**，職責分開：

| 投影 | 回答什麼 | 不負責什麼 |
|---|---|---|
| 引導（`Guide`） | 這類決策可能漏想哪些考量 | 不先推薦特定方案 |
| 方案剖面（`OptionProfile`） | 各方案在已確認考量上表現如何 | 不決定使用者在乎什麼 |

新增方案時只補方案剖面；發現新盲點時只補引導。一次情境生成的考量清單仍是投影，不回寫成證據真值。

**決策牌的兩面**：

- **正面**：要決定什麼；為何是現在；尚缺哪些事實、能不能決定；可能漏想的考量；確認之後才出選項與主要影響
- **翻牌**：成立條件、風險、可逆性、完整影響、課程依據、「不會選」的診斷入口

**全域最低作答形制**：選項＋理由＋成立條件。個別牌只能在此之上**加嚴**，不得降低。系統可以建議，但**高影響或不可逆的決定不得代選**。

## 五、五類邊界與三種提問（來源：問／邊界整合整理稿）

專案裡「邊界」與「提問」各是一詞多義，混用會出事，所以先分清楚。

**五類邊界（物件層）**：

| 名稱 | 定義 | 產物 |
|---|---|---|
| 知識邊界 | 學習者「整塊會／整塊不會」落在**邊**上，不穿模塊中間 | 拆併回饋；已知與未知集合 |
| 決策資訊邊界 | 決策當下「已知／不可知」可乾淨切割 | 當下資訊集；霧戰正面只給當下可知 |
| 文本證據邊界 | 原文未續寫的線不得續造；跨源須標來源 | 「原文未展開」標記；證據引用須指對源 |
| 機制可檢驗邊界 | 機制假設必須可檢驗；對照驗機制、不驗選擇對錯 | 四判定；失效條件 |
| 分流類型邊界 | 文本是否具備決策點、資訊遮蔽、可驗證機制 | 文本卡三要素 |

**三種提問（引擎層）**：

| 名稱 | 問什麼 | 成功長什麼樣 | 站位 |
|---|---|---|---|
| **知識前沿輪** | 沿邊的未知模塊：你會不會 | 邊界畫在邊上；必要時拆併 | 併入模塊拆選 |
| **決策缺口前沿** | 卡在某張決策牌時：最小缺哪一塊知識 | 只補對應模塊 → **回到原牌**再選 | 導航模式 |
| **訓練對照作答** | 選擇＋「如果 X，因為機制 M，導致 Y」 | 對照層判機制 | 訓練模式（本稿不展） |

**已裁決的重點：知識前沿輪與決策缺口前沿共用同一套出題器零件**，不建第二套引擎，差異全走參數：

| 參數 | 知識前沿輪 | 決策缺口前沿 |
|---|---|---|
| 觸發 | 拆選診斷 | 決策受阻，卡在某張牌 |
| 種子集 | 整課候選池沿邊 | 只從卡住那張牌的缺口起，不遍歷整課 |
| 外擴權限 | 第二循環起可沿前沿外擴 | **禁外擴**；補完最小知識必須回原牌 |

**三個引擎共用的紀律（全部適用於導航）**：

- 題目、選項、機制須有原文或可指模塊的證據，不憑空
- 診斷或測驗之前**不先給建議答案**
- 不得代使用者回答「知不知道」，不得代選高影響選項
- 不因結局追認決策品質；風險評估停在當下資訊集
- 選擇題各選項字數等長，不以格式洩題
- 出題以**思考為主軸**：測推導與機制（能講為什麼、能重建），不出逐字複述題

## 六、循環思考四步（來源：循環思考草案，已裁生效）

導航途中的「思考」站執行的就是這個循環。每輪四步：

| 步 | 動作 |
|---|---|
| **重建** | 不看原文，自己講機制與為什麼。**第一性原理紀律**：先列本輪不可再退讓的假設與約束，再往上組機制；**禁止以「別人通常這樣／課文慣例／類比照搬」當理由**（可當對照素材，不得當重建依據） |
| **對照** | 回原文與模塊證據檢驗重建，標記落差；證據須可指，不憑空 |
| **定缺口** | 落差落在哪個模塊或哪條邊上；「整塊不會」可回饋成拆併訊號 |
| **最小一步** | 下一輪只補一個最小缺口，或觸發退出 |

**退出條件（任一即出）**：一輪內沒有新缺口；缺口屬於「缺知識」而非「缺思考」；演講場次宣告開始。

第一性原理是**重建步內的紀律，不是新站、不是新卡型、不是新引擎**。

# 第二部｜三種順序（本稿新增的釐清）

這一節原稿沒有明寫，但不寫清楚會導致設計判斷出錯，2026-07-25 對話中確認。

同一篇文本上同時存在三種順序，**互不相等**：

| 順序 | 由誰決定 | 載體 | 進不進導航排序 |
|---|---|---|---|
| **文本順序** | 作者怎麼敘述 | 字元區間線性層 | **不進**（結構層明文禁設順序邊） |
| **結構順序** | 命題之間的支撐關係 | 邊圖，含長程伏筆邊 | **不進**（邊已退出步層，只當驗收素材） |
| **導航順序** | 你的抵達判準＋當下缺口 | 旅程、站、步 | **這一種才是** |

**實測佐證**：試跑回放頁 27 拍中有 22 拍掛得回原文字元區間，起點序列是

```text
2119 → 3084 → 4998 → 3084 → 4435 → 4998 → 5613 → 6454 → 6898 → 6454 → 8985 → 8419
```

出現 **3 次往回跳**。導航確實沒有照文本順序走，也沒有照邊圖的拓撲順序走。

**因此可以推出兩條判斷**：

1. **模塊不能當步的落點。**理由不是「會變成照順序讀」（那是錯的推論），而是：模塊層明文規定模塊不承載任何流轉狀態，一旦當落點就得記「走到哪」；而且邊會重新爬回步層，那正是已裁決砍掉的東西。
2. **但模塊團可以當缺口取用證據的中介。**既然結構順序可以跳，一個缺口拉出來的模塊團**本來就不必在原文相鄰**。這條是開放選項，見第六部。

# 第三部｜完整規則

## 一、一句話

以**終點**（一篇文本或一個專案）為導向，先寫下**抵達判準**，再由**缺口清單**推出**站**（可預排，也可隨走隨封）；站內走**最小決策循環**；不會就補**最小知識**；每個最小可執行動作計一**步**，抵達每站時累計步數。

## 二、旅程（Journey）

一次以終點為導向的場次。完整欄位：

| 欄位 | 中文 | 說明 |
|---|---|---|
| `destination_kind` | 終點類型 | 文本／專案 |
| `destination_ref` | 終點指向 | 文本識別碼或專案識別碼 |
| `arrival_criterion` | **抵達判準** | **唯一必填的內容欄**。一句「你怎麼知道你到了」。本旅程內鎖定不可改 |
| `gaps[]` | 缺口清單 | 每走一步重算 |
| `gates[]` | 站清單 | 預排的站或走出來才封的站 |
| `step_log[]` | 步紀錄 | 只追加，不修改 |
| `steps_total` | 總步數 | 由步紀錄推導 |
| `evidence_mode` | 證據模式 | 文本型／專案型 |
| `closed_reason` | 結案原因 | 終點訂太大時填「終點過大」並開新旅程繼承 |
| `open_intervals[]` | 未封站區間 | **規格漏欄，試跑時被迫自行補上**，見第六部 |

**邊界**：旅程只消費證據層，**不回寫**模塊或邊的真值。

**終點鎖定**：抵達判準一經寫下即不可改。要改就等於開新旅程，繼承舊的步紀錄與已封站鏈，舊旅程結案。理由是：缺口即方向，終點漂移會讓缺口清單跟著漂，永遠前進卻到不了。

## 三、抵達判準

宣告終點時**不排站**，只寫一句「你怎麼知道你到了」。有了它，任何時刻都能問「離它還缺什麼」——缺口即方向，不需要預排路線。

試跑用的實例（Graph Engineering 五步版文本）：

> 拿到一份多步 Agent 需求時，我能畫出可並行、可驗證的圖，說得出每條邊為什麼存在，並說出這次為什麼該用圖而不是直線。

**砍終點的唯一合法路徑**：當缺口淨增顯示終點訂太大時，**不是改判準**，而是結束本旅程、開新旅程；新旅程繼承舊的步紀錄與已封站鏈，舊旅程標記「終點過大」結案。鎖定不破，退路也在。

## 四、缺口（Gap）

| 欄位 | 中文 | 說明 |
|---|---|---|
| `statement` | 能力陳述 | 一句「在情境 X 下能產出 Y」。**不得寫成模塊名或章節名** |
| `evidence_refs[]` | 證據引用 | 模塊或邊的識別碼，只引用；可以空，空的話標記「無證據」 |
| `unlocks[]` | 解鎖 | 本缺口消掉後解鎖的下游缺口，供候選排序 |
| `verify` | 驗收方式 | 見第六節 |

**反退化紅線**：

> 缺口**不是**模塊集合。一個能力缺口通常對應數個模塊；讀完全部模塊不保證會，只會其中幾個也可能已達成。顆粒由「能不能獨立驗收」決定，不由模塊數決定。**缺口清單一旦等於模塊清單，整套即退化為課綱。**

**候選生成與排序（三層分工）**：

| 序 | 用途 | 說明 |
|---|---|---|
| 文本順序 | 攝入期與講圖用 | 作者順序＝說明順序，**不是**決策順序；不進導航排序 |
| 主軸序 | 導航預設骨幹 | 主軸識別是**啟發式**：找「詳述」與「動機」兩種邊的匯聚點 |
| 抵達判準 | 裁剪權威 | 與本次終點無關的主軸分支不進站 |

**主軸識別只是啟發式**：目前只在兩份文本上驗過，且第二次驗證的領先幅度只有三比二，改判一條邊就會翻轉。因此它**可被抵達判準推翻**，不寫成硬規則。

**每走一步的引導**：每完成一步重算缺口，給 2～3 個候選下一步，各標所消缺口；排序權重＝該缺口能解鎖的下游缺口數。**使用者選，系統不代選。**

## 五、站（GATE）

一個站＝**一個子目的＋一個過站條件**。注意：這個「站」與「決策前置閘門」是兩個不同的東西，不要混。

| 欄位 | 中文 | 說明 |
|---|---|---|
| `gate_id`／`title`／`intent` | 識別／標題／意圖 | 此站要達成的子目的 |
| `gate_origin` | 站的來源 | 預排／走出來才封 |
| `pass_rule` | **過站條件** | 必須可檢驗。**寫不出過站條件的不得當站** |
| `entry_deck` | 進站牌組 | 進站時的最小決策子圖，動態組牌，非固定課綱 |
| `steps_to_arrive` | 抵達步數 | 自上一站（或起點）到**本站通過**為止的步數 |
| `evidence_refs[]` | 證據引用 | 過站所用的模塊與邊，只引用 |

**站的三不變式**（預排站與走出來的站都適用）：

1. **可判定**——寫得出過站條件
2. **有阻擋性**——沒過會讓後面做不動；不阻擋的是站內選配，不是站
3. **值得停**——失敗時願意停下來補；不值得停的併入相鄰站

**兩種站的差別只在過站條件何時寫**：

| 來源 | 適用情況 | 過站條件的時機 |
|---|---|---|
| **預排站** | 站序清楚，例如史實節點明確的決策域 | 進站**前**寫 |
| **走出來的站** | 站序未知，靠缺口滾動 | **封站時反寫**，但必須在驗收之前 |

**封站四步（順序不可調換，這是防自欺的核心）**：

```text
① 宣告某個缺口消掉（使用者主動）
② 先寫過站條件（＝該缺口的驗收句）      ← 必須在跑驗收之前
③ 跑驗收
④ 通過才封站，並回填抵達步數
   未通過 → 缺口留著、該段不封、繼續走
```

**為什麼順序這麼重要**：如果允許走完再照著做過的事回填過站條件，那句條件必然通過，等於免驗。這一條是整套模型裡少數真正承載誠實的規則之一。

**站的五條禁止**：

1. 禁止把模塊樹直接當站樹
2. 禁止自動「一個模塊一個站」
3. 禁止走完再回填過站條件
4. 邊只當驗收素材，**不決定站序**（邊不等於站與站之間的連線，邊也不等於步）
5. 不預排整條路線（預排站除外）

**走完留下的站鏈**可作為同終點的**建議路線**，但**不是必修課綱**，可以跳過。

## 六、步（STEP）

**判準（取代型別白名單）**：一個步＝一次讓旅程狀態改變、且不可再拆的**使用者輸出**。三個條件必須同時成立：

1. **留痕**——有使用者產出的內容：選擇、理由、補的知識、改的路
2. **改狀態**——牌完成／缺口填補／路徑變更／位置前進，至少一項
3. **不可再拆**——拆成兩半後任一半無法單獨留痕

**核心五型（鎖死，不得新增）**：

| 型別 | 中文 | 計一步 | 說明 |
|---|---|---|---|
| `decide` | 做決定 | 是 | 完成一張決策牌：選項＋理由＋成立條件 |
| `q2_fill` | 補最小知識 | 是 | 卡住時補一塊最小知識 |
| `reroute` | 改路 | 是 | 改路徑、增刪牌 |
| `resume_card` | 回原牌 | 是 | 補知後回到原牌，與做決定分開計 |
| `execute_next` | 執行下一步 | 是 | 執行已選的下一步 |
| `domain:` 前綴 | 領域特有動作 | 是 | 照計，但不進核心統計 |
| 純翻牌、重讀、瀏覽 | — | **否** | 無留痕、不改狀態 |

換領域時只能加 `domain:` 前綴型別，五型本身鎖死。

**合併規則**：同一回合「補最小知識 → 回原牌 → 完成決定」計三步，不是一步。理由是誠實反映成本，不灌水。

**歸屬規則**：步歸屬「動作**發生時所在**的站」，不是它服務的站。

**未封站期間的歸屬**：走出來的站是消缺口當下才封的，動作發生時往往無站可掛。因此步先掛**未封站區間**，封站時把該區間整段歸入新站，抵達步數即該區間長度。**旅程結束仍未封站的尾段保持無站狀態**，計入總步數但不計入任何站——不得為了讓帳好看而硬塞給相鄰站。

## 七、驗收：邊當素材，前沿輪當引擎

**邊在導航裡只有一個用途**：當站的驗收素材。它已經退出步層——一步一步走的時候不需要圖。

四種邊型都可用，每條自帶字元區間，天生是可判定的題。驗收問的是「**能不能自己重建這條邊**」，不是「記不記得」：

| 邊型 | 中文 | 驗收句模板 |
|---|---|---|
| `depends_on` | 依賴 | 說明 X 為何以 Y 為前提，缺了會怎樣 |
| `solves` | 解決 | 說明 X 解掉什麼問題，不用它的代價是什麼 |
| `elaborates` | 詳述 | 說明 X 如何把 Y 具體化，**而非換句話說** |
| `motivates` | 動機 | 說明問題如何促成這個定義 |

**放棄的做法**：用「依賴」邊做前提閉包自動補洞。理由是實測十九條邊只有六條可用，閉包太淺。缺口改由**驗收不過時暴露**——較晚但較準。

**缺口驗收＝前沿輪的第三種參數化**（不新增引擎）：

| 參數 | 知識前沿輪 | 決策缺口前沿 | **缺口驗收** |
|---|---|---|---|
| 觸發 | 拆選診斷 | 決策受阻 | 宣告缺口消掉時 |
| 種子集 | 整課候選池沿邊 | 卡住那張牌的缺口 | **該缺口引用的邊** |
| 外擴權限 | 第二循環可外擴 | 禁，必回原牌 | **禁，只驗收不擴散** |

**兩套判定允許不一致（明文，不得當缺陷修）**：

- 知識前沿輪的判定管「**模塊會不會**」→ 餵拆併與間隔繼承
- 缺口驗收管「**能力達成沒有**」→ 餵過站

因此會出現兩種情況，皆屬正常，不得互相覆蓋：①模塊全判會但過不了站（會零件不會組裝）②過站但模塊未判會（能產出但知識不完整）。

**成本線**：驗收停在缺口層，**一趟 3～7 題**，**不得**下放到模塊層逐一測。

## 八、卡住時的補知循環

無法完成某張牌時：

```text
診斷該決策的最小知識前沿
→ 只補對應模塊（不遍歷整課、不外擴）
→ 必須回到原牌再選
```

診斷前不先給建議答案。計三步：補最小知識、回原牌、後續做決定。

**「看過內容」不算完成。**必須回到原決策並實際重選。

## 九、指標與自檢

**三個指標（不比絕對值）**：

| 指標 | 定義 | 用途 |
|---|---|---|
| 缺口減少率 | 每步平均消掉幾個缺口 | 無量綱，可跨文本比，回答「這篇文本對我難不難」 |
| 原地打轉警訊 | 連續 N 步缺口未減 | 提示改路、拆站，或承認終點訂太大。**N 暫定 3** |
| 缺口淨增記帳 | 走的過程發現新缺口 | 正常，但**淨增即訊號**——終點過大或文本撐不起，該砍終點而非硬走 |

總步數**僅在同一旅程內有意義**（站間比、重跑前後比）；跨文本不可比，不設步的權重規則。

**三條退化警訊（自檢）**：

1. 站數約等於模塊數 → 退化成課綱
2. 每站抵達步數都是 1 → 站太鬆，或作答太淺
3. 某站超過 8 步 → 站太大，或缺前置知識該補成獨立站

## 十、專案型終點

終點是專案而非文本時，可能沒有對應模塊。此時以站為主、步由系統即時引導。**三條界線**：

1. 標記為專案型，與文本型**分流，不共用驗收邏輯**
2. 系統給的候選必須標明依據＝**使用者提供的專案事實**；未確認者一律標「假設待證」，不得當事實推進
3. 過站條件由**使用者的產出物本身**承擔（引不到邊），因此專案型驗收**必須留痕**，比文本型更嚴而非更鬆

## 十一、走一趟長什麼樣（完整流程）

```text
【起點】
宣告終點（一篇文本或一個專案）
    ↓
寫下抵達判準（唯一必填，一經寫下鎖定）
    ↓
列出初始缺口清單（每條＝一句能力陳述，非模塊名）
    ↓
┌───────────────── 主循環 ─────────────────┐
│                                          │
│  系統給 2～3 個候選下一步                  │
│  （各標所消缺口，依下游解鎖數排序）         │
│      ↓                                   │
│  使用者選（系統不代選）                    │
│      ↓                                   │
│  ┌─ 有預排站 → 進站，組進站牌組            │
│  └─ 無預排站 → 不進站，直接動作            │
│      ↓                                   │
│  決策前置閘門判定（三出口，本身不計步）      │
│      ├─ 足夠 → 展開考量與方案              │
│      ├─ 不足可等 → 先查證                  │
│      └─ 不足不能等 → 強制風險決策           │
│      ↓                                   │
│  決策牌：正面五欄 → 翻牌六欄                │
│      ↓                                   │
│  ┌─ 能決定 → 選項＋理由＋成立條件〔一步〕   │
│  └─ 不能決定 → 補最小知識〔一步〕          │
│                → 回原牌〔一步〕            │
│                → 再決定〔一步〕            │
│      ↓                                   │
│  執行下一步 / 改路（各一步）                │
│      ↓                                   │
│  重算缺口清單、更新指標                     │
│      ↓                                   │
│  ┌─ 缺口未消 → 回主循環頂端                │
│  └─ 使用者宣告某缺口消掉                   │
│         ↓                                │
│      【封站四步】                          │
│      ① 宣告缺口消掉                        │
│      ② 先寫過站條件（在驗收之前）           │
│      ③ 跑驗收（沿該缺口引用的邊出 3～7 題）  │
│      ④ ┌─ 通過 → 封站，回填抵達步數        │
│         └─ 未過 → 缺口留著、不封站、繼續走   │
│                                          │
└──────────────────────────────────────────┘
    ↓
達成抵達判準 → 旅程結束
    或
缺口淨增持續 → 終點過大 → 結案，開新旅程繼承
```

## 十二、刻意不做（完整清單）

- 不要求先學完才開始任務
- 不把固定課綱改名為牌組或站樹
- 不預排整條路線（預排站除外）
- **不把缺口寫成模塊集合、不逐模塊驗收**
- 不追求跨文本總步數可比，不設步的權重
- 不代選高影響決定
- 不把一次情境路徑回寫成通用知識真值
- 不自動「一個模塊一個站」
- 不修改領域規範、不開路線事項、不實作執行環境或命令列工具
- 不合併三種提問為單一提問站
- 不對股價或市場做預測式結論

# 第五部｜為什麼會感覺卡住（本次新增的診斷）

原稿沒有這一節。2026-07-25 對話中提出「規則被迴圈繞回去」，經核對屬實。

## 一、問題不是規則變多，是規則互相定義

模型裡幾乎每個物件都用**別的模型物件**定義。定義在模型之外的只有兩個東西：

1. **抵達判準**——使用者自己寫的一句話
2. **字元區間**——原文

其餘全部互相指涉。自我指涉的系統要能停下來，**每個環上必須有一個外部終止條件**。目前一個都沒有。

## 二、五個環

| 環 | 誰定義誰 | 現況 |
|---|---|---|
| **一、站與步互相定義** | 站的抵達步數要先有步；步的歸屬要先有站 | **已解**。用「未封站區間」打破：步先掛無站狀態，封站時整段歸入。殘留：旅程結束的尾段永遠無站——試跑真的留了兩步 |
| **二、缺口與驗收互相定義** | 缺口「由驗收不過時暴露」；驗收「宣告缺口消掉時才觸發」 | **未解**。要有缺口才驗收、驗收才生缺口。唯一入口是抵達判準推出的初始清單，之後就自轉。試跑新增的那個缺口就是這樣冒出來的 |
| **三、終點鎖定與砍終點** | 抵達判準不可改；但缺口淨增又要求砍終點 | 用「不改判準，改開新旅程繼承」打破。**但新旅程也有一個鎖定判準，也可能太大 → 再開一個。沒有說第幾次要停** |
| **四、封站、過站條件與驗收** | 封站要過站條件；過站條件要在驗收前寫；驗收過才封站 | 用「四步時序」打破。**但沒過就缺口留著、繼續走、再宣告消掉、再寫、再驗——沒有「試幾次算放棄」** |
| **五、主軸與複驗** | 一份文本歸納的主軸規則不夠 → 降為啟發式 → 「下一份文本須複驗」 | 試跑做了第二份，領先幅度三比二、改判一條邊就翻轉 → **結論是「建議第三份再驗」。複驗的出口是再一次複驗** |

## 三、根因

草案自己寫過：四個補丁的共同理由是原設計「各留一個自我腐蝕點」。但四個補丁做的事都一樣——**把環拉成螺旋**，讓它不要當場死鎖。

螺旋不會鎖死，但**也不會停**：每繞一圈換一個新識別碼（新旅程、新缺口、下一份文本），看起來在前進，位置沒變。

## 四、順帶量到的一件事：一個決定要過幾關

上一棒口頭提過「一次決定要過十四關，承載誠實的只有三關」。實際照規則數下來是**十六道**：

| # | 關卡 | 性質 |
|---|---|---|
| 1 | 決策前置閘門三出口判定 | 防呆 |
| 2 | 決策牌正面五欄 | 內容 |
| 3 | 決策牌翻牌六欄 | 內容 |
| 4 | 最低作答：選項 | **誠實** |
| 5 | 最低作答：理由 | **誠實** |
| 6 | 最低作答：成立條件 | **誠實** |
| 7 | 步的三條件判定 | 記帳 |
| 8 | 步的型別歸類 | 記帳 |
| 9 | 步的歸屬（哪個區間或哪個站） | 記帳 |
| 10 | 宣告缺口消掉 | 流程 |
| 11 | **先寫過站條件（在驗收之前）** | **誠實** |
| 12 | 驗收出題（3～7 題，須指得出邊證據） | **誠實** |
| 13 | 驗收作答判定 | **誠實** |
| 14 | 封站回填抵達步數 | 記帳 |
| 15 | 缺口清單重算與指標更新 | 記帳 |
| 16 | 三條退化警訊自檢 | 記帳 |

**六道承載誠實**（防自欺：防止「看過＝會了」、防止事後回填必然通過的條件、防止系統對自己點頭），可再收成三類：**先寫過站條件**、**獨立驗收**、**留痕**。

**七道是記帳**（步數、歸屬、指標、警訊）。記帳本身不產生任何學習效果，它服務的是「之後可以回頭分析」——而目前沒有任何人在做這個分析。

這就是第六部「路 B」的依據。

# 第六部｜要裁的內容

## 先裁這一項，其餘大半自動消失

**第 0 項：關卡密度——十六道砍成三類，還是保留完整模型？**

| 選項 | 內容 | 後果 |
|---|---|---|
| **路 A** | 保留完整模型，逐項補齊 | 要裁下列 12 項 |
| **路 B（建議）** | 只保留三類承載誠實的規則——**先寫過站條件／獨立驗收／留痕**——其餘記帳類規則整批刪除 | 下列第 5、6、7、8、11 項**直接消失**，只剩 4 項要裁 |

**建議路 B 的理由**：七道記帳關卡服務的分析目前沒有人在做；而這套東西的目的是產出可用的學習物件，不是產出一套可觀測的系統。記帳可以之後真的需要時再加回來，成本遠低於現在維護它們製造的待裁面。

**若裁路 B，剩下要裁的只有四項**：第 1、2、3、4 項。

---

## 完整待裁清單

### 第 1 項：驗收通過門檻——幾題答對算過站？（最卡）

- **現況**：規格**完全沒有值**。試跑自己定「全對才過」
- **為什麼卡**：這個值直接決定站封不封。沒有值，每次實作各自解釋，兩次跑的結果不可比
- **選項**：①全對才過 ②三分之二以上且不得答錯「依賴」型的題 ③使用者自訂，每個旅程開始時宣告
- **建議**：②。理由是「依賴」型題測的是前提關係，答錯代表結構沒懂；其他型別答錯多半是表述問題

### 第 2 項：驗收沒過怎麼重試？（同時是環四的終止條件）

- **現況**：**無規則**。試跑自己決定「只重跑沒過的題」
- **為什麼卡**：只重跑沒過的題，門檻會逐次變鬆（前面對過的不用再對）；而且沒有重試上限，理論上可以無限重試到過為止
- **選項**：①重跑整組，重試上限 2 次，超過強制改路或拆站 ②只重跑沒過的題，但重試上限 1 次 ③不限次數
- **建議**：①。這一條同時給環四裝上終止條件

### 第 3 項：缺口素材不足怎麼辦？（最卡，且與模塊自由度直接相關）

- **現況**：兩個問題疊在一起——
  - 缺口只引得到 1～2 條邊時，**湊不滿「一趟 3～7 題」**。試跑有兩站踩到，被迫外借別的邊、甚至出了一題非邊題（違反「題目須指得出邊證據」）
  - 標記「無證據」的缺口在文本型**根本無素材可驗**
- **為什麼卡**：成本線與「題目須指得出邊證據」互相打架，兩條規則同時生效時無解
- **關鍵判斷**：這**有一半責任在切分，不在規格**。試跑只抽 15 條邊對 14 個模塊，平均一個模塊 1.07 條邊，太稀。而模塊切分依領域規範**可自動調整、不受治理限制**，重切一次是合法且便宜的
- **選項**：
  - ①**先不改規格**，把五步版文本正式收錄，補到每個缺口至少引得到 3 條邊，再用同一份抵達判準重跑同一趟，用證據判斷這個問題是不是切分造成的
  - ②允許沿「解鎖」關係向鄰接缺口外借邊，並標記為外借
  - ③允許缺口先指一個**模塊團**、再由模塊團展開邊（結構順序可跳，模塊團不必在原文相鄰）。**注意這條與「缺口不是模塊集合」的紅線只差一線**：合法的是「缺口的證據取用路徑可經模塊團展開」，違規的是「缺口就是模塊集合」。差別在缺口的身份，不在有沒有碰模塊
  - ④把「無證據」缺口降為「不封站的持續缺口」
- **建議**：先做 ①。若補足邊密度後問題自己消失，②③ 都不必開；④ 無論如何都該做，因為原文沒寫的東西本來就驗不了

### 第 4 項：初始缺口清單怎麼生成？（同時是環二的終止條件）

- **現況**：**無規則**。誰列、列幾條、從抵達判準怎麼推，全部沒定義。試跑靠人工手感列了 6 條
- **為什麼卡**：整趟旅程的起點靠手感；不同人列出的清單不可比，兩次跑的結果也不可比
- **選項**：①由抵達判準拆 4～7 條能力句，每條須指得出至少 1 條邊，否則標「無證據」 ②使用者自列，系統只檢查格式 ③系統列候選，使用者刪改
- **建議**：①，並加一條上限——**一趟最多開幾個缺口，超過即代表終點太大**，這給環二裝上終止條件

### 第 5 項：候選權重平手時怎麼排？〔路 B 下消失〕

- **現況**：無次要排序鍵。試跑第一步就遇到兩個候選權重都是 2，只能全丟給使用者
- **選項**：①次要鍵取證據引用數少者優先（＝驗收成本低者優先）②維持全丟給使用者 ③照缺口建立順序
- **建議**：①

### 第 6 項：驗收作答算不算一步？〔路 B 下消失〕

- **現況**：驗收作答明明有留痕、也改狀態，卻不屬核心五型，而五型已鎖死無法新增
- **選項**：①比照前置閘門判定不計（試跑作法）②加為第六型（但這會破壞「五型鎖死」）
- **建議**：①

### 第 7 項：缺口減少率用總值還是淨值？〔路 B 下消失〕

- **現況**：兩種算法差 0.08（0.33 對 0.25），規格沒說用哪個
- **建議**：用**淨值**，並單獨列「新發現缺口數」

### 第 8 項：原地打轉警訊誤報〔路 B 下消失〕

- **現況**：試跑觸發了一次，但是**誤報**——原因是驗收沒過之後的補知重試，不是走錯路。這時叫使用者改路是錯的
- **建議**：補一句「同一缺口的補知重試區間不計入連續未減步數」

### 第 9 項：同一終點最多開幾次新旅程？（環三的終止條件）

- **現況**：**無規則**。終點太大 → 開新旅程繼承 → 新的也可能太大 → 再開，無限
- **建議**：第二次開新旅程時，**必須縮小終點的範圍寫法**，不得只換識別碼

### 第 10 項：主軸複驗做到幾份才定案？（環五的終止條件）

- **現況**：第一份不夠 → 降為啟發式 → 「下一份須複驗」→ 第二份領先三比二邊際薄 → 「建議第三份再驗」
- **建議**：**做到第三份就定案**——成立就寫成規則，不成立就直接改成「使用者指定主軸、系統只給候選」。不再往下一份推

### 第 11 項：未封站區間補進旅程欄位表〔路 B 下消失〕

- **現況**：這個欄位只在補丁的文字裡提到，旅程欄位表沒有它。實作時無處存放
- **建議**：直接補欄，不需討論

### 第 12 項：回放頁技能放哪裡？

- **現況**：只裝在使用者層（`~/.claude/skills/journey-playback/`），換機器需重裝
- **選項**：①維持使用者層 ②在專案 `.agents/skills/` 再放一份
- **建議**：①。兩份技能說明檔會漂
