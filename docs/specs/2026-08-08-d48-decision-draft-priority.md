## 0. 目的

以 D48 為新的整體主幹，重新檢視目前 `裁1～裁4` 是否仍阻塞主流程、是否需要改題、以及應該先裁哪一件。

本稿只整理**優先順序與重寫方向**；不替使用者直接採納裁1～4 的 A／B 選項，也不把舊裁決題目強行視為仍完全適用。

---

## 1. 主幹基準

D48 將系統分成三種模式：

```text
WORK：把事情做成
  ↓ 能力不足
LEARN：局部補能力 → 返回原 WORK 節點
  ↓ 需要正式結論
VERIFY：限制證據與結論權限 → 返回 WORK
```

因此，現有裁決草案的優先性應改用下列問題判斷：

1. **是否決定 WORK 要不要切進 LEARN？**
2. **是否決定 LEARN 補完後能不能可靠返回 WORK？**
3. **是否阻塞第一輪真實 WORK→LEARN→WORK 試跑？**
4. 若只影響跨趟體感、熟練度統計或後續顯示，則後置。

VERIFY 目前由 D32～D34 獨立承接；現有裁1～4沒有一案直接阻塞 VERIFY。

---

## 2. 新優先順序

| 優先 | 裁案 | 新主幹判斷 | 處置 |
|---|---|---|---|
| **P1** | **裁1** | 決定「這是人的能力缺口，還是資源／工具／原文缺口」，直接影響 WORK 是否切入 LEARN | **最高優先；先重寫再裁** |
| **P2** | **裁4** | 決定進入 LEARN 後怎麼補、何時算足以返回原 WORK 節點 | **第二優先；依 RBF1／D48 瘦身重寫再裁** |
| **P3** | **裁2** | 只影響跨趟是否記得「補過了」，不阻塞第一次主循環 | **後置；先維持不繼承，待重跑有摩擦再裁** |
| **P4** | **裁3** | 熟練度計點已被 D38 移出導航主線；不影響 WORK／LEARN 切換與返回 | **最低；脫離 D48 主幹，等 R／技能登記真的需要再處理** |

一句話：

> **先裁「要不要進 LEARN」，再裁「怎麼從 LEARN 回來」；跨趟記憶與熟練度統計都不能排在主循環之前。**

## 3. P1｜裁1：保留問題核心，但必須改題

### 3.1 舊題

舊裁1問：

> 原文「有提但沒展開」時，算空位還是卡點？

舊選項把判準放在「能不能生得出題」或「文字是否出現」。這是舊文本型導航語境下的問題。

### 3.2 D48 後真正要裁的問題

D48 的切換條件不是「能不能出題」，而是：

> **WORK 卡住時，這個阻塞到底屬於人的能力缺口，還是工具／整合／來源／資源本身不足？**

建議重寫成路由判準：

```text
WORK 卡住
→ 工具／API／組合故障？       → 留在 WORK 排錯／替換
→ 沒有可用來源／資源／能力？   → 留在 WORK 找替代／新增資源
→ 資源存在，但人不會操作／判斷？ → 切入 LEARN
```

### 3.3 為何最高優先

若這一層不清楚，所有失敗都可能被誤送進 LEARN：

- 工具壞掉被誤認成「我不會」。
- 原文根本沒提供資訊，卻反覆叫人重讀。
- 現成能力不存在，卻拿學習流程補一個本來就不存在的輪子。

這會直接破壞 D48 的 WORK／LEARN 邊界。

### 3.4 建議處置

- **不要直接裁舊 A／B。**
- 保留 `裁1` 號與「缺口分類」核心，但依 D48 重寫問題與選項。
- 新版裁1應只負責**路由分類**；不要順便處理補法、熟練度或跨趟狀態。

## 4. P2｜裁4：保留「補與返回」，刪除舊主幹殘留

### 4.1 舊題

舊裁4一次處理四洞：

1. 補什麼材料。
2. 怎樣算補完。
3. 失敗幾次算一次「不懂」。
4. 場次怎麼記。

其中部分內容已被 REBUILD1／D48 重新定義。

### 4.2 D48 後應留下的核心

真正阻塞主幹的是：

> **LEARN 局部補足到什麼程度，才允許返回原 WORK 節點重試？**

應對齊：

```text
WORK 原節點
→ LEARN:L1-02 定位能力卡點
→ L3-01 查資源
→ L3-02 組最小材料
→ L1-04 局部路徑
→ 足以重試原節點
→ L1-05 返回
→ WORK 原節點重試
```

### 4.3 四洞重新處置

| 舊洞 | 新處置 |
|---|---|
| 材料是什麼 | **不再由裁4固定材料種類**；交給 `L3-02` 依卡點組最小材料 |
| 補完怎麼認定 | **保留，升為裁4核心**；判準應是「足以返回並重試原節點」，不是學完整領域 |
| 失敗計數 | **移出主幹**；若未來要做 telemetry／叫停規則再另處理 |
| 場次紀錄格式 | **降為附屬紀錄**；只需能追到原 WORK 節點、補了什麼、返回結果，不應阻塞流程 |

### 4.4 建議處置

- **不要直接裁舊 A／B。**
- 重寫裁4為「LEARN 補足／返回 WORK 協議」。
- 先只裁主幹最小必要規則；計數與詳細紀錄後置。

## 5. P3｜裁2：跨趟繼承後置

裁2問「場外補過後，下一趟要不要繼承補過標記」。

在 D48 下，它不影響：

- WORK 是否能執行。
- 是否能切進 LEARN。
- LEARN 是否能返回 WORK。
- VERIFY 是否能運作。

它只影響**第二趟以後的體感與提示噪音**。

### 建議

第一輪先沿用既有 B-9 精神：**不建立新的跨趟自評真值**。

只有在至少一次真實重跑後，確定「反覆重標」真的造成可觀察阻力，再回來裁是否需要最小持久狀態。

因此：

> **裁2保留待裁，但不得阻塞 D48 第一輪試跑。**

---

## 6. P4｜裁3：熟練度計點脫離主幹

裁3問「用了但沒過的引用要不要計熟練度點」。

但 D38 已把導航與熟練度拆開：

- 導航只產事件。
- 熟練度由 R／技能登記層橫切處理。

D48 更不需要熟練度點才能完成 WORK／LEARN／VERIFY 切換。

### 建議

- 不讓裁3阻塞任何 D48 主線試作。
- 先保留事件資料，不急著把成敗壓成單一分數。
- 等技能登記層真的需要「引用→熟練度」作決策時，再帶真實資料重裁。

若未來確認熟練度不再作任何流程判斷，可以考慮撤回裁3，而不是為了歷史完整性硬裁。

## 7. 建議實際推進順序

```text
D48 作整體主幹
↓
D49 確認裁決優先與重寫方向
↓
重寫裁1：WORK → LEARN 路由判準
↓
重寫裁4：LEARN → WORK 返回協議
↓
跑一次真實 WORK → LEARN → WORK
↓
若要形成正式判斷，再串 VERIFY
↓
重跑後若真的發生跨趟提示摩擦 → 裁2
↓
只有技能登記需要分數決策 → 裁3
```

### 第一輪成功條件

不要求把裁1～4全部裁完；只要求：

1. WORK 卡住時能判斷是否真的需要 LEARN。
2. 進 LEARN 後能補到足以返回原 WORK 節點。
3. 返回後能再次執行並做 WORK 任務驗收。
4. 需要正式結論時能另進 VERIFY，而不是把 WORK 驗收混成內容證據。

裁2／裁3即使仍未裁，也不應妨礙上述四項。
