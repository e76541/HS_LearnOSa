## 1. 主幹基準

```text
WORK：把事情做成
  ↓ 人的能力不足
LEARN：局部補能力 → 返回原呼叫節點
  ↓ 需要正式結論
VERIFY：限制證據與結論權限 → 返回 WORK
```

主案例是 `WORK→LEARN→WORK`；D48 也允許 `VERIFY→LEARN→VERIFY` 的巢狀能力補足。

裁案優先性依四問判斷：

1. 是否決定 WORK 要不要切進 LEARN？
2. 是否決定 LEARN 補完後能不能可靠返回原呼叫節點？
3. 是否阻塞第一輪真實 `WORK→LEARN→WORK`？
4. 若只影響跨趟體感、熟練度統計或後續顯示，則後置。

VERIFY 由 D32～D34 獨立承接；裁1～4不改 VERIFY 的證據規則，但裁4必須支援 VERIFY 在能力缺口時局部呼叫 LEARN 後返回原驗證節點。

## 3. P1｜裁1：WORK→LEARN 入口已重寫

### 新題

> **WORK 卡住時，什麼情況應留在 WORK 排錯／補資源，什麼情況才切入 LEARN？**

核心邊界：

```text
來源／輸入不存在                  → WORK
工具／API／權限／環境故障          → WORK
能力／服務供給根本不存在            → WORK
資源與工具可用，但人不會操作／理解／判斷 → LEARN
正式主張／採用結論的證據權限          → VERIFY
```

### 選項

- **A：最小診斷後路由**。先取得足以判斷阻塞類型的最小證據，再決定 WORK／LEARN／VERIFY。
- **B：不知道怎麼繼續就先進 LEARN**。進入後再發現是否其實是外部故障。

Agent 建議：**A**。

理由：避免工具故障、來源缺失、能力供給不存在被誤診成人的學習問題。

### 邏輯檢查

- WORK 不會被 LEARN 吞掉。
- L2 尚未備料與來源根本不存在有明確區分。
- VERIFY 的證據權限仍獨立。
- 裁1只處理 WORK 入口，不侵入裁4出口。

## 4. P2｜裁4：LEARN 出口已重寫

### 新題

> **LEARN 的退出條件應是「已具備足以重試原呼叫節點的最小可執行能力」，還是「先在 LEARN 內通過額外驗收，再返回呼叫方」？**

### 選項

- **A：可重試即返回；成不成功交回呼叫方。**
  - 原呼叫節點明確。
  - 返回後的下一動作／判斷明確。
  - 必要最小材料已可用。
  - 立即 `L1-05` 返回原呼叫節點重試。
  - WORK 呼叫則回 WORK；VERIFY 呼叫則回原 VERIFY 驗證節點。

- **B：LEARN 內先通過局部驗收，再返回呼叫方。**
  - 需另設局部題目／模擬／判斷 Gate。
  - 未通過則留在 LEARN 繼續補。

Agent 建議：**A**。

理由：LEARN 的責任是恢復原執行節點的可執行性，不是證明已學會；真實能力應回原情境直接重試。B 會重新引入熟練度／評分器並形成第二套 Gate。

### 舊四洞處置

| 舊洞 | 新處置 |
|---|---|
| 材料是什麼 | 交 L3-02 依卡點組最小材料 |
| 補完怎麼認定 | 保留為裁4核心：足以返回原呼叫節點重試 |
| 失敗計數 | 移出第一輪主幹；有 telemetry／叫停需求再議 |
| 場次紀錄格式 | 降為最小事件紀錄，不作返回 Gate |

### 邏輯檢查

- LEARN 不負責 WORK 任務驗收或 VERIFY 證據判斷。
- `L1-05` 不依熟練度分數。
- WORK 返回後失敗會重新走裁1路由，不會無限留在 LEARN。
- VERIFY 呼叫 LEARN 後返回原 VERIFY 節點，不會錯層回 WORK。

## 5. 裁1與裁4現在形成完整一對

WORK 主案例：

```text
WORK 卡住
→ 裁1：要不要進 LEARN？
   ├─ 外部缺口 → 留 WORK
   └─ 人的能力缺口 → LEARN
                      ↓
                  局部補能力
                      ↓
→ 裁4：何時返回原呼叫節點？
                      ↓
                WORK 原節點重試
```

VERIFY 巢狀案例：

```text
VERIFY 驗證中出現人的能力缺口
→ LEARN 局部補能力
→ 裁4：何時返回原呼叫節點？
→ VERIFY 原驗證節點繼續
```

責任分離：

- 裁1＝**WORK→LEARN 入口分類**。
- 裁4＝**LEARN 通用出口條件**。
- WORK＝**真實執行與任務驗收**。
- VERIFY＝**證據與結論權限**。

## 10. 第一輪成功條件

1. WORK 卡住時有一致入口判準。
2. 進 LEARN 後只補必要能力。
3. 能精確返回原呼叫節點重試。
