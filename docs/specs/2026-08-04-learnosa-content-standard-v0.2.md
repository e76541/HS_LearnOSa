## 1. 定位

頻道定位：

> 用開發日誌記錄技術、工具與資料問題的實作過程，並以分級驗證判斷是否值得繼續、採用或深入研究。

預設受眾：

> 正在以實際專案學習技術、資料分析與 AI 工具，並需要判斷下一步是否值得投入的人。

LEARNOSA 是承載文本、學習拆解、實作紀錄與複習的個人學習系統，不是對外品牌，也不是固定評分模型。

本標準只規範內容製作與驗證，不建立一套與本專案無關的共同風險規則。資料來源與使用權只在數據型題目中檢查；重大實務建議則依 L3 規則處理。

## 2. 兩種工作紀錄

### 2.1 驗證項目

驗證項目是正式驗證的工作單位，由以下內容組成：

- 一個驗證問題。
- 一個驗證等級。
- 一項事前設定的本項完成條件。
- 實際驗證結果與相應判斷。

所有等級共用上位詞「驗證問題」：

- L1 使用「探路問題」。
- L2 使用「決策問題」。
- L3 使用「研究問題」。

### 2.2 開發日誌

開發日誌用來保存實作過程、卡點與當下想法，本身沒有 L1／L2／L3 等級。

- 可以獨立存在。
- 可以關聯一個或多個驗證項目。
- 可以在驗證進行中、完成或中止後發布。
- 可以包含暫時觀察，但不能冒用正式判斷詞。
- 若準備作出是否繼續、採用、推廣或深入研究的正式判斷，必須建立或關聯驗證項目。

開發日誌與 L1 的分界在目的：

- 只保存過程，是開發日誌。
- 事前設定要觀察的訊號，目的是判斷是否值得繼續投入，是 L1。
- 日誌寫出下一步，不會自動變成 L1。
- 同一段工作可以同時形成開發日誌與驗證項目，但相同內容不必重寫。

## 3. 分類方式

每個驗證項目使用三個分類維度。

### 3.1 問題領域

初始領域如下，可在真實題目出現後擴充：

- 運動：棒球、籃球。
- 農漁畜：農業、漁業、畜牧。
- 金融市場。
- 港口營運。
- 學習系統。
- AI 技術。
- 軟體開發。

AI 只是協助寫程式、整理文字或探索方向時，不把題目歸入 AI 技術；只有驗證問題本身在問 AI，才使用此領域。

### 3.2 驗證類型

驗證類型可以複選，並決定要套用哪些類型提醒：

- 程式庫／框架。
- 數據分析。
- AI 評估。
- 自動化流程。
- 方法比較。
- 文獻分析。
- 概念分析。
- 軟體／應用原型。

### 3.3 成果形式

成果形式描述驗證物的類別，例如：

- Notebook、程式、查詢檔。
- 表格、圖表、資料字典、資料集。
- Dashboard、流程模板。
- API、網站、行動應用、網頁應用、桌面應用、遊戲。

軟體成果可另外使用多軸標籤：

- 運行形式：行動應用／網頁應用／桌面應用。
- 系統範圍：前端／後端／全端／API 服務。
- 產品形式：工具／Dashboard／網站／遊戲等。

「App」只作「行動應用」的別名；靜態展示頁歸為網站，具有持續互動或應用邏輯才標為網頁應用。

## 4. 等級與完成條件

### 4.1 等級底線

等級底線由本標準固定，表示少於哪些內容就不能完成該級判斷。

### 4.2 本項完成條件

本項完成條件由製作者在開始前依具體問題設定，但不得低於等級底線。

- L1 寫在「試」的觀察目標中。
- L2 寫在「驗」與「界」中。
- L3 寫在「方法與判定規則」中。

看到結果後不得為了結案而降低完成條件。已完成原定驗證時，應依實際結果作出該級判斷；尚未完成便放棄時，才標為驗證中止；若要縮小範圍，另開後續項目。

### 4.3 等級選擇

驗證等級由預定結論權限決定，不由工時、資料量、內容長度或題材難度決定。

實際最低等級，是「預定結論權限」與「L3 強制觸發條件」要求中的較高者。

- 可以自願選擇高於最低要求的等級。
- 命中 L3 強制條件時，不能保留原主張卻使用較低等級。
- 若不需要強結論，可以縮小問題或降低結論權限，再使用 L1 或 L2。
- 自願使用 L3 時仍須完成完整 L3，不存在輕量 L3。

## 5. 驗證狀態

驗證狀態只屬於驗證項目：

| 狀態 | 定義 |
| --- | --- |
| 想法 | 尚未開始實際驗證。 |
| 驗證中 | 已開始執行，但尚未達到等級底線並作出判斷。 |
| 驗證完成 | 已達到該級底線並作出相應判斷；負面結果也可以完成。 |
| 驗證中止 | 已開始，但在取得該級最低所需結果前決定結束。 |

L1 取得可核對阻礙並完成探路判斷，屬於驗證完成，不是驗證中止。L2 與 L3 仍須依各自的等級底線結案；單有阻礙不會自動構成驗證完成。

開發日誌中的「本次進展」只是該篇日誌的文字摘要，不形成另一套全域狀態。

## 6. L1｜探路

### 6.1 目的與結論權限

L1 回答：是否出現足以決定下一輪投入方向的第一個訊號？

L1 只能作探路判斷，不能提出採用建議、重大實務建議或跨情境推廣。

### 6.2 准入

開始前只寫一句：

> 用 X 對 Y 做一次嘗試，要觀察 Z。

Z 是中性的觀察目標，不是預設成功答案。

### 6.3 固定結構

1. **試**：用什麼做什麼，要觀察什麼。
2. **見**：實際看到了什麼，附可見結果或可核對阻礙。
3. **判**：從三個判斷詞中選一個。

探路判斷：

- **另開後續項目**：目前方向值得再投入；後續可維持 L1，也可升級。
- **換方向另開項目**：目前方向不值得繼續，但另一方向值得測試。
- **不再投入**：目前沒有繼續驗證的價值。

無論選哪一項，當前 L1 都先結案。

### 6.4 等級底線與停止條件

L1 的完成條件是：

> 取得第一個足以對照 Z 並支持「判」的可見結果，或確認阻止觀察 Z 的可核對阻礙。

中間查詢、畫面或暫時錯誤留在同一驗證項目或開發日誌，不會因第一個任意輸出出現就強制結案。

單純工作時間結束不算停止條件：

- 還會回來處理，維持驗證中。
- 決定放棄且沒有最低成果，標為驗證中止。
- 已取得足以判斷的結果或阻礙，標為驗證完成。

### 6.5 可見結果

可見結果必須是實際嘗試後產生，且能對照 Z 的輸出，例如：

- 畫面、表格、圖表、程式輸出、模型回應。
- 查詢結果、原型行為、錯誤紀錄。
- 附來源的關鍵摘錄、定義或主張對照表。
- 案例、反例、概念關係圖或分類草圖。
- 初步資料清單與缺口紀錄。

「大概可行」「有學到東西」或純心得不算可見結果。

### 6.6 可核對阻礙

可核對阻礙至少要指出：

1. 卡在哪一個具體步驟。
2. 實際觀察到什麼錯誤、空資料、權限缺口或不相容條件。
3. 為什麼它阻止本項完成條件。

不要求證明永遠無法完成，但只寫「資料不好找」或「工具不能用」不算。

### 6.7 L1 發布

發布 L1 驗證報告時必須標明它是探路結果，展示實際輸出或阻礙，且不能寫成採用或重大實務建議。

## 7. L2｜決策驗證

### 7.1 目的與結論權限

L2 回答：對特定對象與情境而言，某方案是否值得採用？

L2 的結論只對「決」與「界」宣告的範圍有效，不得推廣到未驗證對象或情境。

### 7.2 准入與固定結構

開始前完成「決／驗／界」，執行後完成「果／擦／判」。

1. **決**：誰在什麼情境下，要決定是否採用什麼。
2. **驗**：用什麼小型真實案例、準則與輸出驗證。
3. **界**：包含與不包含什麼，到哪裡停止。
4. **果**：得到什麼可核對結果，並附驗證物。
5. **擦**：主要成本、失敗、限制與意外。
6. **判**：從五個 L2 決策判斷中選一個。

### 7.3 等級底線

L2 必須：

- 完成決／驗／界／果／擦／判。
- 完成事前宣告的驗證與停止邊界。
- 提供足以核對關鍵輸入、條件與輸出的驗證物。
- 說明適用對象、情境與限制。

L2 不要求完整研究級重現；它只要求別人能核對「在這些輸入與條件下，確實得到這個結果」。

### 7.4 L2 決策判斷

| 判斷 | 定義 |
| --- | --- |
| 建議採用 | 在本項設定的對象、情境與限制內，最小驗證足以支持採用。 |
| 有條件採用 | 只有在明列條件成立時才值得採用。 |
| 暫時觀望 | 已有足夠結果判斷現在不宜採用，並能指出重新評估條件。 |
| 不建議採用 | 已有足夠結果判斷在既定情境中不值得採用。 |
| 證據不足 | 已完成預定驗證，但結果不足以在前四項中選擇。 |

「證據不足」是有效結論，因此可以是「驗證完成＋證據不足」。未能執行預定驗證便放棄，才是驗證中止。

### 7.5 比較題目的缺項處理

- 找不到的比較項目標為「無法取得」，不能記成零分。
- 可用代理指標，但必須說明它代理什麼、不能代表什麼。
- 代理指標無法回答同一決策問題時，不得用來排名。
- 缺少次要項目時，縮小結論並揭露限制。
- 缺少必要項目時，L2 判為證據不足。

比較依據的優先順序：

1. 同條件直接測量。
2. 可重現的官方或公開證據。
3. 已揭露限制的代理指標或估算。

## 8. L3｜研究驗證

### 8.1 目的

L3 檢查主要主張是否具有研究級證據，以及證據能支持到哪一種行動結論。

每個 L3 驗證項目只有一個主要研究問題與一個主要主張。可以記錄從屬主張，但需要獨立方法或另一行動判斷時必須另開後續項目。

### 8.2 強制觸發條件

準備作出的主張命中以下任一項時，最低必須使用 L3：

1. **因果主張**：宣稱 X 導致 Y，而非只描述相關或預測。
2. **跨情境推廣**：把結果推到未直接驗證的對象、時間或環境；只提出未來可能性不算。
3. **重大實務建議**：準備直接支持真實行動，且錯誤可能造成明顯後果。
4. **解決證據衝突**：多個 L2 結果互相矛盾，而本項要提出較穩定的統整結論。
5. **外部可靠性主張**：宣稱方法、基準、工具或資料成果具有足以讓外部使用者依賴的可靠性或有效性。

單純把程式、模板或資料整理成可重用成果，不會自動觸發第五項。

未命中強制條件時仍可自願使用 L3。

### 8.3 證據可行性檢查

L3 啟動前做四項是／否檢查：

1. 必要證據能否明確指出並取得。
2. 證據來源與產生條件能否追溯。
3. 證據與方法能否區分支持和不支持。
4. 能否在本項設定的資源界線內完成。

數據型題目才追加「資料可行性檢查」：

- 涵蓋範圍是否適合主張。
- 資料來源與使用權是否清楚。
- 主張是否需要基準真值，以及能否取得。

官方資料不是固定要求；只有主張需要官方事實時才必須使用官方資料。

處理方式：

- 全部通過，才把 L3 從想法移入驗證中。
- 不通過時，縮小主張、更換方法，或維持想法。
- 啟動後才發現條件不成立，依事前資源界線結案為「無法判定＋暫不作建議」；若沒有行動問題，行動判斷標為不適用。

### 8.4 固定八部分

1. **研究問題、主要主張與範圍**：要回答什麼、候選答案是什麼，以及不能推到哪裡。
2. **既有依據與相反觀點**：正式定義、相關來源與已知爭議。
3. **證據與材料設計**：需要哪些證據；數據型才補樣本、遺漏、偏差、來源與使用權。
4. **方法與判定規則**：步驟、指標、本項完成條件、停止條件與資源界線。
5. **比較、反證與替代解釋**：基準、干擾因素，以及什麼結果會推翻主張。
6. **結果與不確定性**：主要輸出、誤差、失敗案例與限制。
7. **穩健性與重現**：必要的敏感度或換條件檢查，以及可重現材料；不適用時說明原因。
8. **結論與下一步**：證據判斷、適用時的行動判斷、專業把關狀態，以及是否另開後續項目。

八部分固定存在，但不要求每種題目都進行統計控制或樣本外測試；不適用時說明理由。

### 8.5 證據判斷

| 判斷 | 定義 |
| --- | --- |
| 支持 | 證據足以檢驗主要主張，且在原定範圍內達到支持標準，不需新增條件。 |
| 條件支持 | 證據足夠，但主要主張只在事前宣告的較窄條件或子群中成立。 |
| 不支持 | 證據足以檢驗主要主張，但未達支持標準或結果與主張相反；不代表已證明相反主張。 |
| 無法判定 | 證據、方法或可比較條件不足，無法合理區分支持與不支持。 |

執行後才發現的新族群、時間區間或情境，只能標為探索性發現；原項目仍依事前主張判斷，新條件另開後續項目驗證。

### 8.6 行動判斷

L3 一律需要證據判斷；只有研究問題包含採用或實務行動時才需要行動判斷。沒有行動問題時，標示「行動判斷不適用」並說明原因；不適用不是第六種行動判斷。

| 判斷 | 定義 |
| --- | --- |
| 建議採用 | 證據與實際條件足以支持在既定情境中採用。 |
| 有條件採用 | 只在明列的對象、條件、限制或配套下建議採用。 |
| 暫時觀望 | 已有足夠資訊判斷現在不宜採用，並有明確重新評估條件。 |
| 不建議採用 | 已有足夠資訊判斷在既定情境中成本、風險或效果不值得。 |
| 暫不作建議 | 證據、必要資訊或專業把關不足，尚無資格作行動建議。 |

證據判斷對行動判斷的上限：

| 證據判斷 | 可使用的行動判斷 |
| --- | --- |
| 支持 | 五種皆可；成本與風險仍可能導向不採用。 |
| 條件支持 | 有條件採用、暫時觀望、不建議採用、暫不作建議。 |
| 不支持 | 暫時觀望、不建議採用、暫不作建議。 |
| 無法判定 | 暫不作建議。 |

行動判斷必須簡述它如何由證據、成本、風險與替代方案推導。若建議依賴另一項理由或另一對象，應另開驗證項目。

### 8.7 同一範圍原則

證據判斷與行動判斷必須使用同一驗證項目宣告的對象與情境。從職業球員跳到青少年球員、從個人使用跳到組織部署，或更換決策對象時，必須另開項目。

### 8.8 停止條件

L3 在「方法與判定規則」中事前列出必要檢查，以及資料、時間或運算資源界線。

- 必要檢查完成後立即結案。
- 碰到事前資源界線而證據仍不足，結案為無法判定；有行動問題時為暫不作建議。
- 新問題、補充樣本或新方法另開後續項目，不擴寫原項目。
- 只有事前設定的提前停止規則可以讓 L3 提前結案。

### 8.9 可重現材料

L3 的最低標準是：具有相同資料存取權的人，可以依紀錄重做主要結果。

依題目提供適用項目：

- 資料來源、範圍與取得方式。
- 清理、轉換、查詢或分析步驟。
- 程式、公式、提示、設定與版本。
- 主要預期輸出與核對方式。
- 無法公開的材料及其影響。

原始資料不能分享時，可提供欄位結構、取得說明或公開的小型替代樣本；完全無法讓他人核對主要結果時，不得宣稱已具可重現性。

### 8.10 重大實務建議與專業把關

「重大實務建議」必須同時符合：

1. 內容準備直接支持或指引真實行動。
2. 判斷錯誤可能造成明顯的資金、產能、營運、安全、法規或權益後果。

只做歷史分析、模擬、概念展示，或提出無重大後果的操作建議，不會自動觸發。

L3 若要提出重大實務建議，必須完成專業把關；否則證據判斷仍可完成，但行動判斷只能是暫不作建議。

專業把關由具有相關實務能力、且不是製作者本人者進行。最低紀錄包括：

1. 能力依據。
2. 把關範圍。
3. 日期。
4. 把關結果。
5. 意見處理紀錄。
6. 與製作、工具、方法或採用結果的相關關係。

把關狀態與結果分開：

- 狀態：不適用／未完成／已完成。
- 結果：通過／有條件通過／未通過；只有已完成時才填。

把關結果對行動判斷的限制：

- 通過：仍依證據、成本與風險選擇行動判斷。
- 有條件通過：不能無條件建議採用，條件必須寫入行動判斷。
- 未通過：不能提出採用建議；有明確不宜採用的理由時可判不建議採用，否則暫不作建議。
- 未完成：涉及重大實務建議時只能暫不作建議。

把關後若修改方法、主要證據、適用範圍或行動建議，必須重新把關，或由原把關者確認修改後版本；把關紀錄必須指向實際發布版本。

## 9. 驗證類型提醒

類型提醒不新增固定欄位，也不提高驗證等級：

- L1 只用來提示可以觀察什麼，不要求逐項回答。
- L2 只回答會影響本次決策判斷的相關項目。
- L3 把相關項目整合進八部分，不另抄一份清單。

| 驗證類型 | 核心提醒 |
| --- | --- |
| 程式庫／框架 | 環境與版本、可執行例、輸入輸出、安裝或執行摩擦、已知限制。 |
| 數據分析 | 資料來源與範圍、使用權、可重現清理、遺漏與偏差、異常處理、方法、圖表是否支持結論、相關不冒充因果。 |
| AI 評估 | 固定任務、模型資訊、提示或設定、輸出、變異與失敗案例、適用邊界、成本。 |
| 自動化流程 | 原流程、輸入輸出、自動化步驟、失敗與復原方式、實際節省的時間、步驟或錯誤。 |
| 方法比較 | 同一問題與條件、比較指標、缺項與代理指標、結果差異、選擇建議。 |
| 文獻分析 | 來源範圍與品質、選取方式、引用是否支持主張、相反證據與遺漏。 |
| 概念分析 | 正式定義、相近概念差異、適用邊界、案例與反例、能支持與不能支持的結論。 |
| 軟體／應用原型 | 目標使用者與任務、環境、可執行路徑、輸入輸出、錯誤狀態、已知限制。 |

AI 只是協助一般工作時，不套用 AI 評估；只有模型本身是驗證對象，或其不確定性會影響結論時才套用。

AI 評估的模型資訊：

- L1 至少記錄畫面顯示的模型名稱與使用日期。
- L2／L3 記錄供應者、產品名稱、精確模型 ID 或版本、使用日期、介面，以及會影響結果的提示、溫度或工具權限。
- 查不到精確版本時寫「未提供」，不得自行推測。

## 10. 驗證結果、驗證物與成果形式

- **驗證結果**：實際觀察到的內容與正式判斷。
- **驗證物**：讓別人核對結果的具體材料。
- **成果形式**：驗證物的分類標籤。

例如：

> 成果形式＝Notebook  
> 驗證物＝實際的 `.ipynb` 檔案  
> 驗證結果＝十萬筆資料在指定條件下完成清理

影片、文章與開發日誌屬於發布內容，不自動等於驗證物；若影片是唯一可核對的實際操作紀錄，它也可以同時作為驗證物。

## 11. 發布

### 11.1 發布內容

每一份發布內容有自己的發布狀態：未發布／已發布。驗證項目本身不維護發布狀態，只連結相關發布內容。

內容類型可以複選：

- 開發日誌。
- 驗證報告。
- 修正公告。

發布形式描述載體，例如文章、影片、貼文或互動頁面。

本標準不設定短內容、正式內容或旗艦內容等發布等級，也不要求每題同時製作影片、文章與驗證物。

同一篇內容兼具開發日誌與驗證報告時，兩套發布檢查是內容要求，不是兩份模板；同一段情境、問題、嘗試、結果與驗證物只寫一次。正式判斷以驗證項目為唯一來源。

### 11.2 開發日誌發布檢查

- 已標示日期、情境與本次進展。
- 已記錄處理／嘗試與下一步。
- 有可核對輸出，或明寫尚未產生。
- 暫時想法沒有寫成正式驗證判斷。
- 若關聯驗證項目，已標示其等級與狀態。

### 11.3 驗證報告發布檢查

- 已標示驗證等級、驗證問題與本項完成條件。
- 已達到該級底線並提供驗證物。
- 已揭露限制、失敗與適用邊界。
- 判斷詞符合該等級，且沒有超出證據。
- 已套用相關驗證類型提醒。

### 11.4 修正公告發布檢查

- 已指出原內容、疑點或錯誤及影響範圍。
- 已連結重驗項目與目前有效結論。
- 已同步處理原發布位置。

## 12. 後續項目與停止延伸

完成的驗證項目不在原地擴充；產生新問題時另開後續項目，並引用一個或多個來源項目。

每個後續項目只選一個主要關係：

- **延伸**：由原結果產生新的驗證問題。
- **升級**：保留核心問題，但提高驗證等級。
- **轉向**：原方向不再投入，改問另一個問題。
- **重驗**：原結論出現重大疑點，在相同核心問題下重新驗證；不以提高等級為必要。

若一個後續項目同時看似「升級」與「重驗」，依主要目的選擇：為覆核已有重大疑點的原結論，標為「重驗」，提高等級只記為該項目的驗證等級；原結論沒有重大疑點，只是主動提高嚴謹度，才標為「升級」。

可延伸的理由至少符合一項：

- 原驗證產生會改變判斷的新重要問題。
- 同一方法需要在另一情境重新驗證。
- 有必要與替代方案作公平比較。
- 成果可形成值得重用的工具、資料或方法。
- 觀眾回應集中在同一個未解問題。

以下情況停止延伸：

- 只是在補功能、API、圖表或展示細節。
- 後續不會改變判斷。
- 無法取得可靠證據或建立公平條件。
- 維護成本高於它能提供的判斷價值。

成果可重用只構成延伸理由，不會自動構成 L3；只有宣稱其足以供外部依賴，才命中外部可靠性主張。

## 13. 重驗與公開修正

### 13.1 小修

不影響證據、理解或判斷的拼字、連結、排版與文字修正，可以原地更正，並留下日期與簡短修訂紀錄。

### 13.2 重大疑點

會改變主要資料、方法、核心數字、適用範圍、證據判斷或行動判斷的疑點，必須建立重驗項目。

- 原內容先標示「結論待重驗」。
- 重驗項目的最低等級不得低於原判斷所需等級。
- 較低等級發現可以指出疑點，但不能直接取代較高等級結論。

### 13.3 重驗結果

- 支持原判斷：移除提示，記錄「重驗後維持原判斷」與理由。
- 確認錯誤：原內容標示「已被修正」，並以重驗項目作為目前有效結論。
- 未能支持或推翻原判斷：原內容保留「結論待重驗」；重驗項目照實記錄其判斷，例如 L2 的「證據不足」、L3 的「無法判定」或「驗證中止」，且不取代或恢復原判斷。

「結論待重驗」「重驗後維持原判斷」「已被修正」是提示或關係標記，不是驗證狀態。

### 13.4 公開修正

- 可編輯的原文章、貼文或程式庫說明加入明顯提示與重驗項目連結。
- 難以修改的影片更新說明欄、標題提示或置頂留言；做不到時，在相同管道發布修正公告。
- 重驗項目列出所有受影響的已發布內容及處理方式。
- 內部完成重驗但尚未同步原發布位置時，不能稱為公開修正完成。

## 14. 評估依據與 LEARNOSA

每個驗證項目的評估準則，依相關文本、既有架構、領域標準或本項決策需求取得。

- 使用外部準則時，記錄來源與原始定義。
- 把準則轉成這次可核對的判定方式。
- L1 只需寫觀察目標。
- L2 把準則寫入「驗」。
- L3 把準則寫入「方法與判定規則」。

不保留固定的「LEARNOSA 評估」步驟；LEARNOSA 只保存學習與驗證紀錄。

## 15. L2 可選敘事參考

原 v0.1 的十步流程只保留為 L2 發布時的內容編排參考，不增加驗證義務：

1. 問題。
2. 假設。
3. 範圍。
4. 輸入。
5. 實作／分析。
6. 結果。
7. 摩擦。
8. 評估依據與判讀。
9. 結論。
10. 下一步。

## 16. v0.1 遷移說明

v0.2 取代 v0.1，主要變更如下：

- 製作單位不再是「一個庫」，改為一個驗證項目。
- 開發日誌可以獨立存在，不必先完成驗證項目准入。
- 不再把所有內容強制套入同一組四項准入與十步流程。
- 十步流程降為 L2 可選敘事參考。
- 影片、文章與驗證物不再是每題必做三件套。
- LEARNOSA 不再被描述為固定評分模型。
- 不使用看板式「卡」作正式術語；學習迴路產物稱「使用紀錄」。
- 不建立與本專案無關的全域紅線；資料使用權與重大實務建議依各自規則處理。
- 驗證完成與發布分離；發布狀態屬於每份發布內容。
