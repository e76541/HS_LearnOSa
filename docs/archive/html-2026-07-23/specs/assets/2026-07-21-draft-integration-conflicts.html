36 處真衝突 × 整合建議

點卡片展開。紅＝結構性需先解、橘＝中度、黃＝低。每張附整合建議供裁決。

來源邊詞彙
canonical 結構層depends_on / exemplifies / elaborates / equivalent_to / contrasts / motivates / solves / foreshadows / condition / broader_than（10 型，英文）
演講路線圖依賴 / 對比 / 舉例 / 推論 / 背景（5 型，中文）
TERMINALprereq / broader_than / related / background（4 型）
問題

三套互不對映：推論無 canonical 對應；prereq≈depends_on；related 太泛；「背景」邊 vs background 語義角色（§2.6）混淆。

整合建議
canonical 10 型為唯一儲存真值；兩份呈現層草案各建一張「顯示名→canonical」對映表；推論／related 這類無對應者標「待裁決是否新增」，不得自創儲存值。
草案中宮外八格
九宮雙階段核心命題8 個模塊
演講路線圖主題命題(n/8)8 個演講模塊
TERMINAL模塊本體8 個子區域（定義/公式/案例/邊界/反例/連結/口述/應用）
問題

TERMINAL 把模塊放中宮、子區域放外格，與前兩份「模塊佔格」根本不同構，卻同名「九宮」。

整合建議
明定「九宮＝模塊組成的面」（雙階段／演講）；TERMINAL 那個改稱「模塊細化視圖」或「子區域九宮」，不混用九宮之名。
問題

流程閉環、雙階段都已把管線寫成「原文→組件→模塊」，提問站拆併「落點為組件」；但組件化還是草稿，§12 有 14 項待裁。上游試行草案依賴一個未定案的規則，裁決變動時上游要回改。

整合建議
把組件化 §12 列為三份試行草案口頭驗證的前置裁決；或明定上游試行「暫以組件化 r1 預設為準，裁決後回校」。
問題

canonical 模塊層 §2.1a 有 hooks（story/quote/formula，附屬模塊）；組件化 §4 有 fragment kind（定義/公式/條件/步驟/證據/例子/背景片段，獨立節點）。兩者功能重疊；組件化自己標了「與候選 C5 公式雙記未結重疊」。

整合建議
裁決單一機制：要嘛 hooks 退場由 fragment 取代（須走模塊層 breaking change 評估）；要嘛 fragment 只作儲存層、hooks 保留作呈現層素材標註。並順帶結掉候選 C5。
問題

組件化 §7：Method 的 constraints=作者未給 不擋入宮（只統計）；模塊層 §2.3：同情況是弱策略點，禁生應用型練習。結果該模塊能入宮照講、能出回憶/解釋題、但不能出應用題——規則各自對，但交會點沒旗標，練習生成易漏判。

整合建議
模塊核心加衍生旗標 weak_policy_point（由 constraints=作者未給 機械推導），練習層與九宮共讀；不新增手設欄位。
問題

三份試行草案要口頭跑「提問→挑選→建圖→骰起格→測驗」，材料不限（Black-Scholes 文章即可）；組件化試作明定要 PDF 專業課程（公式密、人事稀），Black-Scholes 是「人事濃」不符。

整合建議
兩軌並行不互擋：先用 Black-Scholes 跑三份試行的口頭驗證（不依賴組件層硬裁決）；PDF 材料另備，專門驗組件化。
