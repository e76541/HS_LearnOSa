# HS LearnEdge 知識視覺化設計

## 目標

建立一個 React 儀表板，讓使用者從同一介面理解 HS LearnEdge 的處理管線、模塊內容與有向結構邊。第一版使用 repo 內真實 `modules.md`、`edges.md` 資料，並保留擴充到多來源切換的介面。

成功條件：

- 分頁一可用儀表板方式看見來源從收錄到 Dynamic View 的完整管線、每階段狀態與數量。
- 分頁二可在三種圖譜模式間切換，且三種模式共享相同的選取狀態。
- 點選任一模塊後，下方固定流向面板顯示上游、本模塊、下游、邊方向、邊類型與證據定位。
- `background` 明確以黃色虛線節點呈現；可作邊端點，但不被當作技能節點、圖式主體或考點。
- 所有顯示內容可溯源至 `module_id`、`char_span` 或 edge record；視圖不回寫正式資料。

## 介面設計

### 全域框架

- 頂部使用兩個主分頁：`管線總覽`、`模塊與連線`。
- 頂部來源選擇器切換文章；第一版預設載入 repo 內可成功解析的第一份 DOC 來源。
- 顯示載入、空資料、格式錯誤與來源待覆核狀態，不把解析失敗誤顯示成零模塊。

### 管線總覽

- 採用已選定的「控制室儀表板」方向。
- 頂部指標卡顯示來源數、有效模塊、背景模塊、結構邊與待覆核數。
- 中央完整管線依序顯示：收錄 → 模塊化 → 抽邊 → 技能對齊 → 練習／Dynamic View。
- 每一階段顯示狀態、產物數與警示；點選階段後顯示其輸入、輸出及規範限制。

### 模塊與連線

同一分頁提供三種檢視模式，使用 segmented control 切換：

1. `焦點鄰域`：選取模塊置中，只顯示一階上游與下游；適合閱讀單一模塊的直接關係。
2. `全圖聚光鏡`：顯示該來源全部模塊與邊；選取後高亮相連路徑、淡化其他節點，保留整體位置感。
3. `論證分層`：依核心主張、支撐方法、實作機制／案例分層；選取後顯示通往概念根的完整有向路徑。

三種模式共用：

- 模塊選取、來源選取、邊類型篩選與是否顯示背景的狀態。
- 節點顯示中文人話標題，角落保留 `module_id`；型別以低干擾色籤呈現。
- 邊使用 canonical 類型與箭頭；方向遵守「來源模塊指向被支撐模塊」。
- `background` 使用黃色虛線外框；不參與論證分層的核心主體排列。
- 下方固定流向面板：上游輸入 → 目前模塊 → 下游流向，另含完整邊帳本與來源證據。

## 技術與資料設計

- 建立獨立 React + TypeScript 前端，使用 Vite 與 React Flow；版面與狀態控制不依賴後端。
- 建置時將 DOC 產物轉為只讀 JSON：`SourceRecord`、`ModuleRecord`、`EdgeRecord`、`PipelineSummary`。Markdown 仍是證據來源，JSON 只是展示投影。
- `ModuleRecord` 至少保留 `module_id`、`source_id`、`char_span`、`module_type`、`semantic_roles`、`is_skill_signal`、`confidence`、標題與本體摘要。
- `EdgeRecord` 至少保留 source、target、type、evidence span 與證據摘要；只接受 canonical 模塊層邊，不載入登記層 `broader_than`。
- 圖譜佈局由檢視模式決定，但不得改變節點、邊、方向或類型。切換模式只改投影，不改資料。
- 第一版為唯讀。沒有任何 UI 操作會更新 `modules.md`、`edges.md`、登記簿或原文。

## 互動與失敗處理

- 切換模式時保留目前模塊；若新來源沒有相同 `module_id`，改選該來源第一個有效技能模塊。
- 隱藏背景時只隱藏背景節點及其顯示邊，不刪除底層資料；重新開啟後恢復。
- 點選邊可在下方面板查看存在性、方向、類型與證據；點選空白不清除已選模塊。
- 缺少 `char_span`、未知邊類型或懸空端點時顯示資料警示，該項不進圖，不推測修補。
- 手機版以全寬圖譜加可收合底部面板呈現；桌面版保持圖譜與固定底部流向面板。

## 驗收與測試

- 解析測試：現有 `modules.md`、`edges.md` 可完整轉成資料模型，模塊數與邊數一致。
- 語義測試：邊箭頭方向、canonical 類型、背景角色及 `is_skill_signal` 呈現正確。
- 模式測試：三種模式切換後保留來源、模塊、篩選狀態，且不改變圖資料。
- 互動測試：點選模塊、點選邊、隱藏背景、切換來源、下方面板內容均正確。
- 異常測試：空來源、缺少欄位、未知邊類型、懸空端點與解析失敗都有明確訊息。
- 響應式與無障礙：鍵盤可選模塊與切換模式，焦點可見，顏色不是唯一狀態訊號，窄螢幕不遮蔽流向內容。
- 完成後執行 production build，並以瀏覽器實際檢查兩個分頁、三種圖譜模式與底部流向面板。

## 明確預設

- 三種圖譜不是三個分頁，而是同一個 `模塊與連線` 分頁內的三種模式。
- 管線採控制室儀表板版型，但優先完成圖譜互動，再完成管線視圖。
- 第一版先使用 repo 現有 DOC 來源；SRC-002 必須在產生正式 `modules.md`、`edges.md` 後才進正式資料選單，不把本次對話中的乾跑結果當成真值。
- 完成品預設可部署；若部署環境不可用，至少交付可執行的本機 production build。
