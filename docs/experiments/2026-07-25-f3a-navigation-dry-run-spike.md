## 3. 逐步走跑（候選 → 模擬作答 → STEP → 缺口重算）

> emergent 期間**不進站**，系統每步給 2～3 個候選、各標所消缺口，依權重排序，**使用者選**。

### 步 S1

**候選（系統）**

| 候選 | 所消缺口 | 權重 |
|---|---|---|
| A. 把一段「然後」流程逐條判真假邊 | GAP-1 | 2 |
| B. 決定 20 個檔案要不要同時跑 | GAP-2 | 2 |
| C. 決定這件事該不該用圖 | GAP-6 | 0 |

**使用者選 A**（權重平手 A/B，系統無 tie-break 規則 → 空洞 H2；本試跑由使用者自選）。

**DecisionCard DC01（全欄）**

| 面 | 欄 | 內容 |
|---|---|---|
| 正面 | 要決定什麼 | 「先摘要檔案，然後查天氣，然後寫報告」這條鏈，哪幾條箭頭該砍 |
| 正面 | 為何現在 | 不判真假邊，後面所有並行決定都建在假前提上 |
| 正面 | 尚缺事實／能否決定 | 需知道每步是否讀上一步輸出；資訊已在題面 → **能決定** |
| 正面 | 可能漏想的考量 | 「順序看起來合理」不等於有資料流動；隱式共用狀態不算變數跨過 |
| 正面 | 選項＋主要影響 | O1 全保留（安全但全程等待）／**O2 砍摘要→天氣**（兩者並行）／O3 全砍（報告會拿不到輸入） |
| 翻牌 | 條件 | 報告節點確實需要摘要與天氣兩份輸出 |
| 翻牌 | 風險 | 誤砍真邊會讓下游拿到空輸入 |
| 翻牌 | 可逆性 | 高：邊是腳本裡的變數傳遞，改回來成本低 |
| 翻牌 | 完整影響 | 牆鐘時間由「串列總和」降為「較慢者」；context 不再被中間結果填滿 |
| 翻牌 | 課程依據 | N03 `[2119,3084)`；N00 `[0,897)` |
| 翻牌 | 「不會選」診斷入口 | 若答不出「哪個變數跨過箭頭」→ 走 Q2 補 N03 |

**模擬作答（U）**：選 **O2**。
理由：天氣不讀摘要的任何輸出，兩者之間沒有變數跨過；報告讀兩者，所以 fan-in 那兩條是真邊。
成立條件：報告節點必須同時吃到兩份輸出；若報告只用摘要，天氣連真邊都沒有，應整個砍掉。

**STEP**：`decide`（留痕✓ 改狀態✓〔牌完成〕 不可再拆✓）→ **S1**。缺口重算：GAP-1 尚未消（只答了題面例，未套自己的流程）。

### 步 S2

**候選**：A. 把自己的 5 步稽核流程重畫成節點與邊（GAP-1）／B. 決定扇出寬度（GAP-2）／C. 該不該用圖（GAP-6）。**使用者選 A**。

**模擬作答（U）**（`execute_next`：執行已選的下一步）：
把「列出路由檔 → 逐檔讀 → 逐檔判 auth → 彙整 → 寫報告」重畫為 3 節點 2 邊：
`scope(列檔)` --檔案路徑陣列--> `audit(每檔一 Agent，20 份)` --findings 陣列--> `report(合成)`；
20 個 audit 之間沒有任何變數跨過 → 彼此無邊。

**STEP**：`execute_next` → **S2**。
**使用者宣告**：GAP-1 消掉。→ 進封站四步（§4.1）。

### 步 S3

（GATE-E1 已封，見 §4.1）候選重算：A. 扇出與收斂（GAP-2，權重 2）／B. verifier 設計（GAP-3，1）／C. 該不該用圖（GAP-6，0）。**使用者選 A**。

**DecisionCard DC02（全欄）**

| 面 | 欄 | 內容 |
|---|---|---|
| 正面 | 要決定什麼 | 20 個 audit 節點要一次扇出，還是分批／照順序 |
| 正面 | 為何現在 | 這決定同時定了成本、牆鐘時間與 context 佔用 |
| 正面 | 尚缺事實／能否決定 | 不確定「同時最多幾個」「超量會不會被丟掉」→ **前置閘門出口 2：資訊不足但可等待，先查證** |
| 正面 | 可能漏想的考量 | 扇出後**收斂在哪一點**；失敗的 Agent 回什麼；一次跑滿的用量 |
| 正面 | 選項＋主要影響 | O1 照順序（慢、可逐步看）／**O2 一次扇出 20＋單一 report 收斂**／O3 扇滿 1000（本次無此規模，純燒錢） |
| 翻牌 | 條件 | 各檔之間無資料流動；報告階段真的需要全集 |
| 翻牌 | 風險 | 併發上限造成排隊；個別失敗污染彙整 |
| 翻牌 | 可逆性 | 高（先跑 20，再放大） |
| 翻牌 | 完整影響 | 協調在腳本、母 context 不裝全部來源；用量仍隨 Agent 數上升 |
| 翻牌 | 課程依據 | N04 `[3084,4435)`、N05 `[4435,4998)`、N06 `[4998,5613)` |
| 翻牌 | 「不會選」診斷入口 | 答不出 1000／16 的關係 → Q2 補 N06 |

**前置閘門判定：出口 2（資訊不足但可等待）→ 不計 STEP**（§7）。

**模擬作答（U）**：選 **O2**。
理由：20 個檔案互不讀對方輸出，是典型的獨立工作；報告需要全集，所以收斂點放在 report。
成立條件：先跑 20 觀察成本再放大。

**STEP**：`decide` → **S3**。

### 步 S4

**候選**：A. 寫出收斂點與失敗處置（GAP-2）／B. verifier（GAP-3）／C. 隔離三問（GAP-4）。**使用者選 A**。

**模擬作答（U）**（`execute_next`）：收斂點寫成一個 `report` 節點，吃 20 份 findings；失敗的 audit 回 null，彙整前先濾掉，report 不假設拿到全 20 份。

**STEP**：`execute_next` → **S4**。**使用者宣告**：GAP-2 消掉 → 進封站四步 → **驗收未過**（見 §4.2）→ **缺口留著、該段不封**，繼續走。

### 步 S5–S7（驗收未過後的補救）

- **S5** `q2_fill`：回讀 N06 `[4998,5613)` 波次段。留痕：「1,000 是單次 workflow 的扇出總量；16 是同時工作數；所以艦隊以波次推進，超量排隊但仍會跑完。」
- **S6** `resume_card`：回到 DC02（未換牌、未改選項）。
- **S7** `decide`：DC02 補寫成立條件——「扇出寬度可大於併發上限；決定依據是用量與可觀察性，不是併發數」。

**STEP**：三步分別計 1（§4.3 合併規則：誠實反映成本）。再次宣告 GAP-2 消掉 → 重跑驗收 → **通過** → 封 GATE-E2。

### 步 S8

**候選**：A. verifier 設計（GAP-3，權重 1）／B. 隔離三問（GAP-4，0）／C. 錨（GAP-5，0）。**使用者選 A**。

**DecisionCard DC03（全欄）**

| 面 | 欄 | 內容 |
|---|---|---|
| 正面 | 要決定什麼 | verifier 跟 audit 共用同一個 session，還是開獨立節點 |
| 正面 | 為何現在 | 放行前的信心是整張圖的槓桿，錯了下游全是綠燈 |
| 正面 | 尚缺事實／能否決定 | 無缺 → **前置閘門出口 1：資訊與權限足夠** |

**STEP**：`decide` → **S8**。宣告 GAP-3 消掉 → 封站四步 → 通過 → 封 **GATE-E3**（`steps_to_arrive=1`）。
